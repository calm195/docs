## 后端接口与消费边界

固定共享契约0.2.0/revision 5原字节保持。主接口沿用正式投影；辅助timeline/work及task/report升级按后端既有T029记录和当前源码消费，未将辅助实现冒充已发布的新共享契约版本。

| 路径（统一前缀/api/v1/admin） | 消费行为 |
| --- | --- |
| GET /crisis-cases | limit20、不透明签名游标；仅保存id/version/status，不保存列表中多余学号、正文或时间线 |
| GET /crisis-cases/{id} | 按需读取授权学号、正文和证据/动作引用；返回ID必须匹配，完整学号默认隐藏，可显式显示再隐藏 |
| GET /crisis-cases/{id}/timeline | 处理人、动作、时刻和理由；以北京时间格式化，拒绝异常时间 |
| GET /crisis-cases/{id}/work | 服务端handoff_at及关怀/人员通知的状态、次数、next_at；投递不推断人工接手，不保存租约字段 |
| GET /evidence/{id} | 只从当前案件明确的evidence引用发起，校验返回证据ID和case_id；不提供任意证据搜索、下载或无关学生卡入口 |
| POST /crisis-cases/{id}/actions | take_over/follow_up/resolve/retry_notification、reason、案件expected_version，稳定Idempotency-Key |
| POST /crisis-cases/{id}/resolve-false-positive | 仅reason和案件expected_version，不发送action或直接上架/送达参数 |
| POST /moderation-tasks/{id}/escalate-crisis | 审核详情按权限发起，使用来源任务版本，不混为新危机案件版本 |
| POST /reports/{id}/escalate-crisis | 举报详情按权限发起，使用举报独立版本，由后端解析精确内容及主体，不在前端构造身份 |

所有请求绑定进入工作区时的内存后台Bearer，no-store、credentials=omit、redirect=error和AbortSignal；请求前、响应后、读体后复核取消/本地权限，unknown边界校验和字段白名单。非200仅保留HTTP状态，不显示内部错误正文。理由沿后端2000 Unicode码点技术预算，中文与补充平面字符不错误按UTF-8字节或UTF-16单元计算。

## 页面、权限与生命周期

新增懒加载/crisis、“危机工作台”菜单，仅crisis_operator和super_admin可进入。review_operator、空角色、未登录不能进入；普通安全治理仍保留原三角色，未扩大其他模块权限。升级组件仅危机角色/超管可见，来源ID/版本由父详情绑定、理由必填、二次确认；成功后清普通案件材料并跳转新危机案件，跳转失败明确告知已有处理结果，不能据此重发。

工作台实现游标分页、首页刷新、空/加载/失败重试，按需详情，独立时间线/待办刷新，限定证据读/收起，完整学号显示/隐藏、操作确认与最小回执。pending_handling/handling可处置，resolved/false_positive和未知状态只读。结案保留危机隔离；误报仅解除本案危机限制并回普通复核，不直接公开、送达或解除其他处罚/屏障；通知重试只请求人员投递，不宣称已通知或接手。

北京时间8–22时人工窗口与夜间服务端交接时刻可见，无首响SLA或倒计时。当前后台没有关怀卡正文读取接口，工作台只显示关怀投递状态，不冒用学生/me关怀接口，不内置或编造热线/校内预约资料。

相同命令结果不明重试沿用幂等键；409清旧决定/理由并重读当前案件，禁止自动重提。404清案件并给出资源失效/接口未装配提示；401清会话、403清页面并进入拒绝流程。辅助读取401/403同样清主详情、完整学号和证据；切案/翻页/离页/换会话/撤权取消请求并丢弃旧响应；收起证据后即使在途读取晚到也不恢复材料。身份、正文及理由不持久化、不记录到日志。
