## 配置与启动

Go配置入口已统一为Viper独立实例，使用严格字段映射并关闭弱类型转换；不接入环境变量或热更新，业务代码不直接导入go-yaml，后者仅为Viper间接依赖。公共配置合并、数组替换、零值覆盖、带单位时长、Base64密钥及多行秘密均有配置回归；未知空映射、弱类型和紧凑别名写法也纳入负例。应用只读原文件，保留注释与原私有值。

唯一应用配置为 `configs/common.yaml` 加 `configs/development.yaml` 或 `configs/production.yaml`；后者为Git忽略的私有环境覆盖。示例及公共字段均有中文注释，嵌套映射合并、数组替换，拒绝未知字段、重复键和null。原口令、令牌、CA和唯一应用主密钥 `masterkey` 内联私有YAML，环境变量不能覆盖。主密钥由HKDF-SHA256按环境与固定用途标签派生子密钥，API/worker保持一致；旧用途密钥字段全部拒绝，供应商凭据和外部KMS引用仍独立配置。主密钥和环境名不可在有数据后直接更换。配置用途、详细字段与命令统一维护在[配置与启动说明](../../../liyuanci-backend-go/CONFIGURATION.md)。

每个环境仅有一组 `database` 分项字段（host、port、name、user、password、sslmode、timezone、connecttimeout），程序转义后生成唯一连接；旧 `database.dsn` 字段拒绝加载，API、五类worker、显式迁移和初始化使用同一数据库账号/进程内连接池。该账号拥有专用业务库对象，拒绝superuser、BYPASSRLS及集群管理权限；学生/后台身份、岗位、归属和版本检查由各业务方法执行。旧多角色库需显式转换对象所有权和撤销不用的登录身份，普通启动不做转换。

本机私有开发连接已拆为对应字段，保留原数据库口令、应用主密钥和其他凭据，不连接或迁移现有数据库。公共配置提供5432端口、UTC时区和5s连接超时；生产模板默认verify-full，使用系统信任根并校验主机名。开发host仍需按实际可用原生实例填写。

删除恢复改用独立加密文件账本，不再需要第二条DSN；保留原恢复密钥、历史意图、跨进程锁、原子替换与fsync。已有生产日志库不能直接换成空文件，必须先迁移核对意图；本次未接触生产库。同机文件不代表独立故障域。

## 当前无MQ原生装配

MQ客户端、传输层、独立消息worker、Dockerfile、Compose、旧systemd模板、按角色生成配置及旧运维入口已删除。API与五类worker直接运行Go二进制，`scripts/manage.py` / Makefile统一执行配置检查、启动、迁移、初始化与任务。中间件由宿主管理；普通启动不建库、不迁移、不初始化账号或自动启停PG/Redis。

学生卡、普通内容、树洞审核/胶囊继续扫描PostgreSQL持久任务，保留租约、重试、取消和幂等；账号及证据清理继续使用持久待办和恢复门禁。按同一环境配置启动各进程，使用 `-kind` 选择职责。未来目标机的服务管理、资源预算、日志和告警须按实际主机配置验收，旧systemd模板不再作为当前交付物。

用户明确要求不备份并删除相关Docker资源。本机已删除本项目43个容器、29个卷、15个网络以及相关镜像；旧配置/备份和旧制品已删除。随后用户明确允许清空当前开发数据并切换单主密钥；私有开发覆盖已替换18个旧用途密钥字段，生成一个随机主密钥，保留其他外部凭据；`.local/data` 中两个旧对象文件已清除，无旧账本文件或本轮备份。未连接或清空远程/生产数据库。Docker数据库数据已删除，日常开发需将数据库分项字段/Redis地址配置为可用原生实例。此次资源清理只涉及本机本项目，未操作候选服务器。清理完成时已核对资源清单；末次复查时Docker引擎socket已不存在，未重新启动引擎。
