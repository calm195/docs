### 4.2 私有运行配置

从[关闭状态模板](../../../../liyuanci-backend-go/configs/examples/whispers-runtime.json)准备API、内容、账号隐私、证据清理四份私有JSON，文件名在下文为示意，尚未创建。只在隔离integration环境按准入启用 `Enabled=true`。四份配置使用同一业务语义、密钥及资源版本，各进程只提供自身所需DSN；业务库一致，恢复日志库独立。

必须核对：API五个业务角色池、内容domain-worker、账号privacy-maintenance、证据evidence-purger；恢复读／写池；七个互不复用的32字节Base64用途密钥；业务及恢复KMS的当前／历史引用；HTTPS `GatewayURL`、令牌文件、CA与ProviderVersion；带版本的 `CatalogFile` 及关怀资源；以纳秒表示的期限。保持密钥、口令、正文和DSN不入库、不输出。

网关需要health能力校验、wrap／unwrap、public_analysis、private_classify、redact、erase、notify等适配；仓库没有可直接作为正式供应商使用的默认成功服务。人工审核不能替代这套树洞依赖。已有开发 `manual` 仅适用于旧心愿／应愿／聊天／故事内容流程；开发学生卡扫描和学校规则仍有模拟边界。

首轮可在树洞配置中明确 `DatabasePolling=true` 并不设置MQ文件，仅记轮询通过。测试MQ时使用独立review／unlock topic、producer／consumer group，先在所选Broker创建主题，再设置两份MQ文件；未复跑MQ不能把历史MQ证据记成本轮通过。

私有API YAML示意如下；路径、Redis地址／认证必须替换为实际交接值，不能原样复制执行：

```yaml
environment: integration
devappfile: /绝对路径/business.host.json
whispersfile: /绝对路径/whispers-api.json
database:
  driver: postgres
  dsn: devapp

  enabled: true
  address: 127.0.0.1:16379

  enabled: false

  address: 127.0.0.1:18080
```

`devappfile`保留真实微信／后台登录及旧业务，`whispersfile`叠加树洞路由。只启动树洞组件不会创建登录入口或模板账号。宿主已注册的安全／注销路由会被复用，因此还须核对旧业务与树洞之间的授权、回执、恢复日志及历史密钥引用兼容，不能仅凭同一数据库判定整合成功；网关必须能够处理本环境允许的历史引用，不得用新密钥替代已有密文的密钥。启动前清理或核对终端遗留 `APP_*` 覆盖，YAML不是最高优先级。

### 4.3 恢复门禁、诊断与常驻进程

若是恢复环境，或冷启动提示删除目标仍存在，先隔离读取／外发，分别运行以下一次性恢复操作；成功退出才继续。失败保持隔离并处理依赖，不删除日志或修改任务状态绕过。

```sh
APP_ENVIRONMENT=integration APP_WHISPERSFILE=/绝对路径/whispers-account.json \
APP_PRIVACY_SCOPE=account APP_PRIVACY_RECOVER=true ./bin/privacy-worker

APP_ENVIRONMENT=integration APP_WHISPERSFILE=/绝对路径/whispers-evidence.json \
APP_PRIVACY_SCOPE=evidence APP_PRIVACY_RECOVER=true ./bin/privacy-worker
```

诊断通过后，API及各worker分别在独立终端前台运行，保留安全启动日志：

```sh
./bin/server -config /绝对路径/joint-api.yaml -check
./bin/server -config /绝对路径/joint-api.yaml

# 另开终端：学生卡、旧内容消费者分别运行
make dev-worker
make dev-content-worker

# 另开终端：树洞审核、胶囊解锁与危机补偿
APP_ENVIRONMENT=integration APP_WHISPERSFILE=/绝对路径/whispers-content.json \
./bin/content-worker

# 另开终端：两个清理范围分别常驻；避免遗留RECOVER=true导致只运行一次
APP_ENVIRONMENT=integration APP_WHISPERSFILE=/绝对路径/whispers-account.json \
APP_PRIVACY_SCOPE=account APP_PRIVACY_RECOVER=false ./bin/privacy-worker

APP_ENVIRONMENT=integration APP_WHISPERSFILE=/绝对路径/whispers-evidence.json \
APP_PRIVACY_SCOPE=evidence APP_PRIVACY_RECOVER=false ./bin/privacy-worker
```

【事实／源码核对】`scripts/localdev.py`会清除外部 `APP_*`，因此 `APP_WHISPERSFILE=… make dev-api` 不会按预期装配树洞；本手册直接调用二进制。旧内容worker和树洞worker消费范围不同，需要分别运行。进程范围及供应商语义见[正式装配记录](2026-10-28-whispers-runtime-r1.md)和[源码README](../../../../liyuanci-backend-go/README.md)。

启动门槛：`-check`成功、各worker无装配错误、目标端口实际监听、业务请求可达且后台／学生鉴权域正确。可以读取 `/healthz`、`/readyz`作诊断，但组合开发入口的ready状态不能替代每个依赖与业务用例；503应记录具体原因及受影响范围，不能忽略相关依赖故障继续宣称通过。

收尾时在直接启动的各终端按Ctrl-C并等待退出；它们不由 `make dev-stop` 的PID记录管理。再用匹配项目的 `make dev-stop` 停止脚本管理进程，按需 `make dev-infra-stop`，保留数据库、卷、对象和原密钥。记录本轮实际保留／停止的服务，禁止沿用历史清理授权扩大删除范围。

## 7. 证据格式、失败处理与收口

每次执行在对应端 `validation/` 新建证据；同一任务尚未固定时复用记录。只保存脱敏材料，页面截图必须遮盖真实身份、学号、敏感正文；不得保存原始HAR、token、Cookie、密码或供应商完整请求／响应。

```text
用例ID／REQ／本次断言：
三端完整SHA／docs基点／契约版本与SHA256：
环境代号／配置引用／迁移及opaque状态／设备与构建模式：
依赖逐项真实或替代：PG、Redis、MQ或轮询、登录、KMS、扫描、资料、通知、清理
账号角色代号（A／B／审核岗等）：
前置条件／步骤／预期／实际：
方法＋模板路径／HTTP状态／脱敏request_id／版本／worker结果：
脱敏页面证据路径：
结果：未执行／子项通过／完整通过／失败／阻塞
未覆盖断言／阻塞RI编号／责任岗位／下次解除证据：
```

连接失败先检查地址、监听、代理及进程；401检查会话与登录域；403检查资格、角色及服务端动作；409按当前版本／幂等／升级码分类；429保留限频预算，等待或隔离测试账号；503定位依赖。不可通过关闭校验、降低安全门槛、改数据库状态或把未知枚举吞掉来获得“通过”。

共享阻塞只由协调者根据证据核销；每个WI区分真实页面、HTTP／故障补测及供应商边界。全部适用断言、依赖和真机证据齐备后才提出完整验收结论；用户审批仍按原流程，AI不签发G1/G2/G3。
