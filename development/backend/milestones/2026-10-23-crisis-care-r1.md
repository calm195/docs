## 实现与接入

【实现】危机流程与现有`internal/moderation`共用不可变正文、扫描及统一命令事务；按文件分离案件、命令、读取与投递。扫描命中在原领域消费事务内写入：独立证据范围、危机案件、用途绑定加密的精确原文和作者学号、当前危机限制、关怀及授权人员通知两条持久待办。四类来源为wish/application/message/story；不复制对端资料、其他私聊或无关学生卡；已取消、撤回、换版或删除的普通任务不能经巡查入口升格为永久证据。事务任一步失败整体回滚；消费重放不重复建案。

| 路由（前缀/api/v1） | 权限与行为 |
| --- | --- |
| GET /admin/crisis-cases、/admin/crisis-cases/{id} | 当前危机角色或超管；列表仅最小元数据，详情才解密该案学号与正文；访问动作写入独立证据时间线后返回 |
| POST /admin/crisis-cases/{id}/actions | action、reason、案件expected_version；动作take_over/follow_up/resolve/retry_notification；记录处理人、时间、加密理由并递增案件版本 |
| POST /admin/crisis-cases/{id}/resolve-false-positive | reason、案件expected_version；仅解除本案危机限制，转新普通人工复核，不直接公开或送达 |
| GET /admin/evidence/{id} | 危机证据范围或该范围唯一证据项标识；只返回限定证据，不返回对象存储键 |
| GET /admin/evidence/{id}/asset | 本轮文字危机案件不包含涉案图片，授权后404；无关学生卡不因危机事件被复制 |
| POST /admin/moderation-tasks/{id}/escalate-crisis | 辅助巡查入口；reason、审核任务expected_version；仅具体已扫描当前内容，不提供任意私聊搜索 |
| POST /admin/reports/{id}/escalate-crisis | 辅助举报升级入口；reason、举报expected_version；使用举报精确绑定内容及其当前审核任务，不信任客户端作者或正文 |
| GET /admin/crisis-cases/{id}/timeline、/work | 辅助工作台入口；完整动作处理人/时刻/理由，以及投递状态、尝试次数、下次重试和人工接手窗口；不返回租约令牌 |
| GET /me/care-cards/{id} | 本人存续学生会话，受罚本人也可读；通知target_ref指向普通数据域卡片，不暴露后台案号 |

【契约边界】主危机/证据接口沿用固定共享投影；CrisisCase.timeline仍为CaseSummary，包含证据项引用及动作摘要。完整处理人/时刻/理由由辅助timeline端点提供；通知保持既有Notification字段，只新增kind=crisis_care。辅助巡查、举报升级、工作台和关怀卡端点以本记录描述本端接入，不原地修改已固定OpenAPI；两端接入时须显式核对这些增量，不能把旧索引的not-implemented当成当前运行事实，也不能据本记录宣布共享版本已发布。

## 关键安全与生命周期

1. 学生、普通审核角色及撤销角色不能读取危机身份或处置危机误报；每次会话和角色复核均来自数据库。后台使用独立`liyuanci_crisis_api`运行组及独立池；普通`liyuanci_admin_api`仍无证据schema权限。领域worker为原子写入限定证据获得明确表级写权限，无DDL或证据清除权限。
2. 已公开心愿巡查升级后在同事务撤下并清除公开投影；故事清除公开正文；应愿留言清除已审投影；已送达消息由当前危机限制隐藏，保留原送达序号。普通审核列表、详情和决定均排除当前危机隔离，不能通过已有普通扫描绕过危机角色。
3. 误报保留历史危机扫描与证据，创建独立普通人工任务，重新绑定原脱敏候选。原任务作废，旧事件不可恢复正文。注销、换版、撤回或交互失效时不重建普通内容；后续普通决定仍检查当前账号、处罚、隐私屏障、期限和匹配资格。已送达消息保持数据库原status/序号约束，通过当前内容审核状态隐藏；普通复核不产生第二次送达或通知，驳回亦不修改历史送达序号。匹配中/已实现/已还愿的心愿及尚存匹配已接受留言只复核内容，不重配或改变业务状态；心愿普通复核后仍须本人显式上架。
4. 内容扫描与危机投递在workrunner中使用独立有界轮询，共用取消和等待生命周期，不叠加两种外部调用的调度预算。关怀和授权人员通知分别使用持久租约；通知在事务外发送，提供稳定投递ID要求适配方去重。崩溃后由过期租约补偿，确认只接受当前租约；失败保留pending和next_at，重启不丢待办。误报取消未完成投递，晚到失败不能将取消任务改回pending；已在途的外部通知只含技术引用，不含身份正文。
5. 机器自动隔离和待办全天运行；北京时间8至22时人工窗口，夜间案件记录下一次8时handoff_at供接手，不新增首次响应SLA，也不把通知送达等同人工接手。resolve结束处置不自动解除危机隔离；只有误报解除走专门权限路径。
6. 援助资料须由宿主显式注入版本、来源、核验日期、24小时援助渠道和校内预约信息；无默认热线或真实资料。资料缺失时关怀待办保持重试；通知适配器缺失亦保留待办，不声称正式通知已送达。普通关怀卡不含危机正文/学号，注销服务须先清理卡片再物理删除账号；独立证据仍按限定案件保留。

## 配置、迁移与依赖

新增0018上/下行迁移，包含案件version/source_task_id/handoff_at、加密动作理由、普通审核crisis_recheck标志、独立危机投递表及普通关怀卡表；新增对象/字段均有中文数据库COMMENT与实体映射。有新危机数据时拒绝丢数据回退，不修改既有迁移。升级须停止旧Go进程，以专用迁移身份显式执行迁移并由管理员重放bootstrap权限；运行启动不执行DDL。

`studentapi.Dependencies.CrisisDB`与`Config.Crisis`同时显式启用后台危机接口，池及游标密钥与其他用途隔离。宿主开发凭据文件新增可选`CrisisDSN`，使用仅属于`liyuanci_crisis_api`的独立受限登录；不自动创建账号或生成替代历史密钥。未提供则不注册危机后台路由。后续分支约定同步更新两仓库AGENTS及docs治理说明；这是用户明确覆盖默认同名codex分支规则，不改变无关前端规则。`Settings.Care`提供可选援助资料，传给内容worker；生产宿主显式注入`moderation.WorkerConfig.Care/CrisisNotifier`，通知接口只接收投递ID和案件ID。日常原生PG/Redis、旧凭据及生产资源不被本轮启停或迁移。

【未完成/依赖】D03正式词库、举报类型、援助资料和实际值班交接、真实通知适配、微信及正式内容分析供应商仍需资源交付及真实接入验收；T030两端页面、T031注销/证据永久删除与全副本恢复不在本轮。文字危机案件不产生资产证据，既有普通违规证据创建/删除不因本轮自动宣称完成。本端隔离测试不能替代三端联调、正式运营资料有效性、性能、恢复或生产验收。
