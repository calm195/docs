# 小程序后续计划

更新：2026-10-30。先完成现有链路的资源补齐与真实验收；不扩展独立搭子、鲤币、语音或媒体。跨端安排见[统一计划](../../plans/README.md)。

| 顺序 | 工作 | 前置/协作 | 完成标准 |
| --- | --- | --- | --- |
| 1/P1 | 补投稿二维码（MP-01）并核对正式资料依赖（MP-04） | 负责人交付真实图片；后端/运营交付有效字典和援助资料 | 无占位联系人；认证/游客边界正确，缺失降级可见，真机可预览且联系路径可用 |
| 2/P1 | 全模块双账号页面回归（MP-05） | 固定当前源码与契约；A/B微信及专用认证身份；管理端角色可用 | 心愿→应愿→匹配→聊天→还愿；树洞/昵称/暖评/抱抱/胶囊；资料/反馈；安全申诉与隐私逐链完成，不能仅用HTTP代替页面 |
| 3/P1 | 真机、弱网与生命周期回归（MP-06） | 双设备、双主题、受控网络和后台切换条件 | 导航返回、登录换号、晚到响应、聊天未发送输入、分页/长历史及键盘布局稳定 |
| 4/P1 | 并发、时间及隐私边界（MP-07） | 后端可控版本/队列、专用删除账号、恢复资源 | 关闭/批准竞争、重试幂等、通知去重、胶囊边界和取消、跨号404无正文、注销屏障逐项通过 |
| 5/P2 | 时间与限流反馈（MP-02/03），补外部行为验收（MP-08） | 明确可用的服务端反馈、真实分享对象与网盘测试资源 | 用户可读时间和等待提示；分享投递/撤回失效、下载和投稿路径实际可用 |

每项按可复现问题补测试并修复，完成后更新现状和缺陷。本端 `npm run check` 是交付门槛，页面/样式/依赖/构建变化另跑微信构建；设备、外部供应商与生产验收单独说明。人员和交付日期未落实前不承诺完成日。
