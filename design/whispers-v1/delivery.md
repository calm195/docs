# 三端独立开发与联合验收 v1.0

本文件对应[方案入口](README.md)、[需求增量](../../requirements/whispers-v1.md)及[契约包](../../contracts/whispers-v1/README.md)。全部实施项尚未执行；用户已采纳首期范围与推荐取舍，语音延期。工作包可独立开发，但首期完成需要文字、互动、本人胶囊及共同治理全部达标。

## 1. 各端共同输入

每端固定消费`whispers/1.0.0`的`openapi.json`、`actions.json`、`examples.json`和交付`manifest.json`，记录指纹。先核对需求及状态机，再生成类型／适配器；Mock仅替换传输且只在测试中运行，不作为产品默认成功路径。任何未知枚举、字段或动作不得由前端宽松吞掉来掩盖契约不一致。

依赖区分：契约未齐阻塞对应适配；后端未就绪时前端可完成组件／替代传输测试；真实资源缺失阻塞真实验收，不能据此把正常UI改成成功模拟。开发期间改接口须另发新版本并同步消费者，不原地改已固定v1。开始前重核源码分支、完整HEAD和工作区。

| WM-06 解忧／通知／举报 | 公共帮助页复用HelpDirectory；模块通知读取／已读与target跳转；举报type_code来自配置，返回列表刷新当前状态 | 不内置真实热线，缺资源可解释；危机关怀卡继续本人授权；通知失效不回显旧内容 |

| WM-08 验证交接 | 按角色／状态／异常fixture检查页面脚本、组件与平台生命周期，后接真实后端／微信工具及真机 | npm run check、build:mp-weixin及差异检查；真实与替代传输证据分开，提交精确源码版本 |

页面路径为实现落点建议，API路径和动作不得变化。全部新页面复用现有AppPage、语义色、导航主题及页面可见性检查；无语音入口、占位录音授权或上传端点。前端不把契约样例文件打进生产默认业务数据。

OwnerPost.status处理：draft显示继续编辑／提交，scanning或review_pending显示处理中，rejected显示理由和编辑，published可管理／撤回，withdrawn可显式重提，restricted／isolated仅显示安全提示及服务端允许动作，privacy_hold不回填正文。OwnerComment.context_changed提示重新读取原帖；post_id=null提示原帖不可用，只有安全recovery_body可供本人另行填写。勿用同一“审核通过”文案概括这些状态。

## 5. 独立开发顺序与汇合点

| 交接点 | 可并行范围 | 汇合要求 |
| --- | --- | --- |
| H0 契约交付 | 后端WB-01／02、小程序WM-01至07、管理端WA-01至04均可按同包独立推进 | 记录包版本／指纹；问题回报不能私自改Wire |
| H1 文字／匿名 | 后端提供post／nickname／help／blocks及普通审核，前端接真实服务 | 草稿→扫描→人工（适用）→公开→撤回；三档匿名及旧黑名单保护同时检查 |
| H2 暖评／抱抱 | H1字段稳定后接评论、开关、计数、通知与治理 | 未认证正常用户、父帖换版、拉黑、处罚、并发抱抱和取消任务全部覆盖 |
| H3 本人胶囊 | 可与H2分别开发；共用扫描／危机及删除基础 | 封存→扫描／复核→到期读取→通知→删除，停机及未认证危机反例完成 |
| H4 首期联合收口 | H1–H3，加WB-04隐私／恢复及原系统回归 | 对应资源均真实核验，首期范围逐项记录，未完成半匿名资料不得藏在“整体完成”中 |

最小先行演示可以是合成资料的文字闭环，但不能称首期交付。缺语音供应商不会阻塞首期；缺文本审核、援助资源、隐私清理或半匿名字典分别阻塞其真实验收，不把已实现的其他子项全部重置。

## 7. 启用清单与文档交付

先完成需求／接口消费与实现检查，再显式迁移、核验权限和workers；升级两端及opaque黑名单后，才启用树洞入口与新数据。不能先开文字公开再补危机或注销。后端回滚不恢复旧黑名单接口，前端降版必须保持升级提示。

各端完成后按[治理规范](../../governance/README.md)新增本端阶段和证据、固定指纹；当前共享设计包通过后固定，滚动计划继续维护实际状态。提交／推送／部署按实际授权执行，设计交付本身不改变Git工作流。本次仅运行契约生成一致性、schema／样例／动作／引用／指纹及文档检查，没有运行上述产品测试或构建。
