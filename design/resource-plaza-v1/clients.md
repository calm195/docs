# 资料广场管理端与小程序设计

日期：2026-10-29。关联 REQ-023、REQ-002、REQ-014、REQ-018、REQ-019。依赖[需求 v1.1](../../requirements/resource-plaza-v1.1.md)、[领域规则](domain.md)及[API提案](api.md)。本文件是页面与交互设计，无页面实现或真机验证结果。

## 1. 管理端入口与页面（023-F–N、Q–T）

菜单建议在“内容管理”分组增加“资料管理”“资料分类”，仅审核运营/超管可见；路由守卫使用同一角色条件，服务端仍逐请求授权。资料不设举报管理菜单，反馈汇总直接进入资料列表/详情。

| 页面 / 拟路由 | 展示 | 动作 |
| --- | --- | --- |
| 资料列表 `/resources` | 分类、状态、关键词筛选；标题、分类、简介摘要、状态、四类反馈计数、创建/更新时间；分页 | 查询、重置、新建、查看；下架资料可编辑/上架，已上架可下架/下架后编辑 |
| 新建抽屉 | 标题、分类、简介、下载链接、提取码；必填及长度提示 | 保存草稿、取消；无“保存并上架”隐式动作 |
| 详情抽屉 | 当前服务端完整资料、状态、四类反馈汇总及允许动作 | 编辑、上架、下架；链接/码以纯文本显示，不自动访问网盘；无反馈学生名单 |
| 编辑抽屉 | 完整字段副本及打开时资源版本 | 保存、取消；只能编辑draft/offline |
| 分类列表 `/resource-categories` | 名称、排序、启用状态；分页；启用状态筛选 | 新建、改名/排序、启用/停用；无硬删除 |

列表和表单分离，遵循当前管理端查询页与右侧抽屉的用法。抽屉打开时保持列表筛选位置，写入期间禁止关闭/重复提交；离开有未保存输入时提示放弃。详情和表单只保留在内存，不写localStorage、埋点、URL或控制台。

标题/简介用文本节点，不使用v-html；链接不渲染自动外跳iframe/预览。字段校验遵循需求及领域规范，简介按码点、URL按UTF-8字节显示长度，提取码不擅自转小写；对缺提取码显示“无提取码”。创建服务端草稿需要完整必填项，未完成表单可取消，不声称已保存。

## 2. 管理端关键流程

**新建与上架**：新建→填写→保存草稿→读取服务端详情→检查内容及链接来源→显式点击上架→提交当前version→成功后重取详情和列表。成功文案用“已上架”，不能宣称外部链接已验证可下载。

**已上架编辑**：点击“下架后编辑”→提示“下架后学生暂不可查看，取消编辑也不会恢复上架”→确认理由→offline命令成功→用返回/重读版本打开编辑→保存→仍保持下架→需要时再次点击上架。不能先打开可保存表单再偷偷下架；下架请求结果未知时保持待确认状态，使用同键同内容核实结果。

**主动下架**：读取最新详情→填写理由并确认→请求下架→服务端成功后清除列表旧状态。若当前筛选只看已上架，目标从列表移除；网络错误保留待重试命令，不将UI行直接乐观标为已下架。

**分类维护**：新建/编辑采用独立抽屉；改名影响所有引用资料的展示名称，提交前说明。停用被引用分类返回CATEGORY_IN_USE，提供按该分类查看资料的入口；不会自动迁类、删除或批量下架。对已上架资料改类仍先逐条下架再编辑。

**反馈维护**：汇总使用固定顺序“有效、链接失效、年代久远、不全”，并说明统计针对当前内容版本。出现负面反馈不自动下架，运营人工核对后按普通流程修改或下架。编辑实质内容时提示“保存新版本后，旧版反馈将清除”；无变化保存或仅下架不清除。不显示学生身份，不提供处罚/举报跳转。

**并发与撤权**：所有写入按“目标+输入+版本+幂等键”保存一次尝试。超时原样重试；409重新读取并提示资料已被修改，保持本地输入但不给它自动套新版本；若新状态为published，禁用保存，必须重新下架流程。401/403/账号切换立即清除详情、表单、在途响应和待重试请求，权限失效不保留敏感草稿。

列表每次查询生成请求代次，只有当前主体/筛选/请求代次的响应可以落屏；取消请求同时也检查代次。筛选修改后禁用旧翻页，查询时清空游标栈；写后刷新首页以得到当前结果，空/错误状态分开。服务端成功但随后刷新失败时提示“操作已成功，刷新失败”，不重复执行写入。

## 3. 管理端代码组织建议

当前源码 `src/router/index.ts` 有角色化菜单和懒加载路由，`src/services/users.ts` 有unknown边界校验，`src/composables/useUsers.ts` 使用工作区和请求隔离。沿用这些模式，新增建议位置：

- `src/types/resources.ts`、`src/services/resources.ts`：正式契约类型、严格解析器和API；业务组件不直接发HTTP。
- `src/composables/useResources.ts`、`useResourceCategories.ts`：查询、抽屉、版本/幂等及当前操作者隔离；临时表单不塞全局store。
- `src/views/ResourcesView.vue`、`ResourceCategoriesView.vue`，必要的详情/编辑组件放 `src/components/`；复用现有表格、分页、抽屉和错误提示。

上述为拟新增文件，当前不存在不表示应立即创建。正式接口样例到位后，测试传输层可使用明确标记的合成响应；运行页面不内置一套模拟成功结果。

## 4. 小程序入口与页面（023-A–E、O–P）

首页增加“资料广场”入口，入口名称及认证引导可对所有用户展示；入口不承载标题、推荐资料、下载数或简介。复用现有学生认证结果，不新增“资料会员”或第二次认证。

| 页面 / 拟路径 | 内容与行为 |
| --- | --- |
| 列表 `pages/resources/index` | 认证门禁；“资料投稿”入口；全部/单级分类选择、关键词输入及搜索/清空；资料卡片与加载更多；不显示链接/提取码 |
| 详情 `pages/resources/detail?id=...` | 标题、分类、完整简介、链接、提取码、更新时间；复制下载信息/仅复制链接；“资料反馈”四选一，无举报入口 |
| 认证引导 | 游客“登录后完成学生认证”；未认证“去认证”；待审“认证审核中”；驳回“查看原因并重新提交”；认证有效再读取 |

封禁显示当前限制及既有申诉入口，不将其误导为重新提交认证即可恢复；禁言且认证有效可读、可复制、可查看投稿二维码，但不可提交/修改反馈。后台凭据不能在小程序换取读权。

页面onShow先复核当前用户再请求分类/资料，加载时不闪现上个用户的旧资料。深链直接打开详情同样验证；资料ID放页面参数仅作定位，标题、链接、提取码和关键词不写导航URL。不新增携带资料摘要的小程序分享卡、好友通知或网盘自动跳转。

## 5. 小程序搜索与复制

关键词点击搜索/键盘确认后请求，首期不做逐字联想。提交搜索、切分类或清空时清空旧游标和卡片；加载更多按当前条件继续，按ID去重，不把同一资料不同版本当两条。无内容显示“暂无符合条件的资料”，请求失败提供重试，未认证显示门禁，模块未装配/服务不可用不能变成空广场。

详情每次再进入重新读取；离开页面清除详情及下载信息，切账号或会话epoch变化清除全部受限数据。列表/详情结果不持久化，已认证标记不是离线通行证。

复制流程：

1. 点击后禁用重复按钮，捕获当前会话epoch、主体、页面代次、resource_id及version。
2. 请求download-info，服务端重新检查资格、上架状态与版本。
3. 仅当前页面仍可见且上述身份/代次匹配时接纳响应；再次检查resource_id/version及字段解析结果。
4. “复制下载信息”使用copy_text，“仅复制链接”使用download_url，调用平台剪贴板能力；成功后提示“已复制”，失败提示“复制失败，请重试”。
5. 请求或校验失败时不使用旧详情数据兜底；重试重新取链。409先刷新并等待再次点击，401/403/404清除旧链接和码。

剪贴板写入是客户端动作；校验后与系统写入之间仍有短暂竞态，不承诺服务端能够收回已经发出的内容。回调到达时页面/会话已变则不再弹成功提示，也不自动清空用户系统剪贴板。HTTP成功不等于剪贴板成功，复制成功不等于外部文件下载成功。

## 6. 小程序反馈与投稿二维码（023-U–W）

详情“资料反馈”显示固定四选项“有效、链接失效、年代久远、不全”；无本人反馈时未选中，有反馈时回显当前选项。用户选择后点击提交，提交中防重复；成功更新本人选择并提示“反馈已记录”，不提示“举报成功”或“已下架”。支持改选，不提供自由文本、联系方式、图片或撤销功能；不向学生展示其他人的反馈或汇总。

提交使用详情content_version及my_feedback.version（无则0），不能拿resource.version代替。失败不把选中状态标为已保存，网络超时保留原命令键；409刷新当前内容/本人选择后等待用户确认，旧响应不覆盖新选择；401/403/404清除受限数据。资料更新后本人旧版反馈不回显，用户可对新版本重新反馈。

列表头部“资料投稿”与筛选并列，空结果时仍可点击。认证门禁通过后，弹出带标题“资料投稿”的弹窗：完整二维码图片、文案“添加资料负责人微信，备注‘资料投稿’”、查看大图及关闭。显示宽度适配屏幕，保持图片比例及二维码四周留白，不裁剪、不叠加水印；打开大图不能导航到任意网盘URL。

固定图片拟置于 `src/static/resource-contribution.png`（实际格式按提供文件确定），通过模块静态配置引用；缺失时构建配置标记未就绪，弹窗明确“投稿二维码暂未配置”；加载失败明确重试，不显示虚构联系图。此处只是拟定路径，本次没有创建占位二维码。替换固定图需要重新构建/发布，记录图片指纹；不新增管理端图片上传、在线编辑或系统内投稿状态页。

提供的图片应为资料负责人指定的联络二维码，完整显示及微信可识别性由真机核验；不假设所有平台都能长按直接识别。二维码弹窗和静态资源无聊天发送动作；关闭弹窗不代表已投稿，扫描后在微信联系的结果不由本系统记录为投稿成功。

## 7. 小程序代码组织建议

现有 `src/pages.json` 注册页面，`src/utils/session.ts` 提供内存token和epoch，`src/pages/wishes/index.vue` 已使用页面可见性、请求generation及会话epoch过滤晚到响应。新增建议位置：

- `src/api/resources.ts`、`src/types/resource.ts`：复用 `src/utils/request.ts`，业务成功码0；区分403认证/账号限制与404资料不可用。
- `src/pages/resources/index.vue`、`detail.vue`：按现有uni-app组件和生命周期实现；在pages.json注册并接入首页入口。
- 必要时新增 `src/composables/use-resource-page.ts` 与纯函数 `src/utils/resource.ts`：共享会话清理、规范化/验证及复制选择逻辑，避免页面各自形成不同规则。

不复制旧公开心愿列表的游客读取规则，也不把现有模拟登录状态当真实认证。使用uni-app剪贴板能力，不用浏览器navigator.clipboard；具体编译平台行为须在后续WeChat真机上验证，当前只确定交互需求。

## 8. 两端验证重点

管理端：角色菜单+直接URL、完整字段/码点边界、先下架再编辑、取消不恢复、版本冲突、超时同键重试、分类占用、反馈汇总无学生身份、不同操作者响应隔离、错误不能误成功。

小程序：游客/四种认证状态/ban/mute、首页无资料泄漏、分类与搜索交集、快速切词和翻页、旧详情下架/换版、不同账号、剪贴板拒绝与重试、反馈改选和过期版本、二维码弹窗/完整图/缺图、无网、onHide/onShow与退出登录后晚到响应。

两端合成测试仅证明页面行为；后端真实状态变更、权限并发、日志不泄漏及微信系统剪贴板结果需要[联合验收](delivery.md)的独立证据。
