## 打开方式

直接用浏览器打开本目录的 `index.html`。所有插画、图标、脚本和样式都在本目录，无远程字体、CDN、运行依赖或业务 API。可整体复制本目录离线查看。

如需本地 HTTP 预览，在项目根目录运行：

```sh
python3 -m http.server 4178 --bind 127.0.0.1 --directory docs/design/prototypes-v2
```

然后打开 [本地预览](http://127.0.0.1:4178/)。结束后按 Ctrl+C 停止服务。

小程序左侧切换页面，中央预览内容区，右侧切换页面状态、提交结果及适用的业务状态；顶部支持跟随系统、浅色和深色三种外观，中央支持 320 / 375 / 430 CSS px 内容宽度。窄窗口中设计说明移到下方。

管理端沿用分组菜单，顶部黑色工具条属于原型查看器，提供角色、页面状态与写入结果选择；它不属于正式产品界面。需要上下文的详情与审核以抽屉打开，简单操作使用列表控件，活动使用独立工作区。角色选择仅演示入口与内容的呈现差异，不实现真实鉴权。

## 重新设计的重点

小程序沿用五个主入口：首页、心愿池、悄悄话、资料、我的。首页按问候 → 水彩主视觉 → 三个快捷入口 → 包分配活动 → 内容信息流排列。插画保持辨识度，减少不必要的装饰性嵌套，统一标签、作者信息、统计和操作层级。

心愿和匿名心事采用不同面色与阅读节奏。详情先呈现正文，再展示统计、评论和操作。资料使用文件类型标识、分类与体积信息。个人页集中账号入口与个人记录，胶囊用信件式布局，并以显式状态决定是否展示正文。

包分配保留薄荷绿、原版搭子插画与既有品牌色，不引入工作区未提交的独立信笺配色。资料拆为“关于我 / 我的期待 / 确认资料”三步；活动展示未报名、待审、等待公布、已配对、已公布未配对和已结束六种状态。

管理端保留紫色强调、白色侧栏与分组导航。工作台将六项现有统计置于首屏，趋势与常用入口并列，热点分区排列；数据列表统一为筛选 → 结果说明 → 表格 → 分页。查看和审核集中到详情抽屉，活动的设置、报名、配对、任务使用独立标签工作区。

源码结构：

原型包含37个小程序页面、登录提示弹窗与详情内回复编辑框，以及33个管理端页面入口（31个业务/账号入口，加403和404）。`routes-mini.json`保留39条基线映射，通过`presentation`区分页面、弹窗和原地编辑；原登录、暖评页面不再保留独立入口。动态详情使用一组可识别的合成记录，不代表已经设计或验证了所有角色、字段组合与异常状态。完整业务字段仍须对照源码及有效契约。

共享状态选择器：正常、加载、空、读取失败、无权限。表单提交支持成功、结果未知和版本冲突呈现。小程序三步资料、通用编辑表单和管理端编辑器保留本次会话的草稿；刷新恢复初始演示，主题选择仅保存在当前浏览器会话。

主要设计路径：

1. 小程序首页 → 许愿 → 表单 → 提交回执 → 消息；心愿池 → 详情 → 应愿 → 接受 → 聊天。
2. 小程序包分配 → 三步资料 → 确认保存；活动详情在查看器切换六态 → 已配对 → 聊天。
3. 管理端内容审核 → 详情 → 选择驳回 → 必填理由 → 确认结论 → 列表状态更新。
4. 管理端活动维护 → 管理活动 → 配对结果 → 生成方案 → 核对并应用 → 确认发布。
5. 管理端资料列表 → 行内下架确认 → 详情编辑 → 行内上架确认；结果未知时从顶部保留的原请求入口核实。
