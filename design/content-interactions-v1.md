## 心愿发布、期限与编辑

### 发布及解除数量限制

用户已明确取消三条活跃心愿限制，既适用于上架，也适用于已实现心愿回退至应愿中等原先受额度限制的路径。同步移除后端额度查询/判断、allowed_actions 的容量分支、小程序满额提示和演示逻辑；原并发用例改为验证四条及更多心愿可以同时生效。正常频率限制、认证、审核、处罚和隐私屏障继续生效。

推荐流程：保存草稿 → 提交发布 → 审核中 → 审核通过后自动上架；拒绝时可修改后重提。“提交发布”记录明确的 `publish_intent`。自动与人工审核通过均进入同一领域事务，重新验证当前内容版本、图片版本、作者资格、发布意愿和屏障；通过后原子更新公开状态及通知。不能只在管理端点击“通过”后调用一次客户端上架请求。

新流程不产生“额度已满待上架”。历史 ready 保留兼容入口，不因升级批量公开；本人主动提交发布或上架后按新规则处理。审核期间撤回须清除发布意愿；旧任务晚到不能重新上架。任务重试不重复发布时间、通知或浏览数。作者收到“已发布”或驳回结果通知。

### 有效期可选至90天

用户已明确90天为可选项。保留现有默认7天，将可选范围从1–30天扩展为1–90天；发布表单建议提供7、14、30、60、90天快捷选项，同时保留范围内的自定义天数。只有用户主动选择90天时才采用90天，不将其设为默认或固定期限。首次期限从成功公开起按所选天数计算，待审不消耗有效期；普通编辑、作者补充和重新审核不自动续期。新增 `first_published_at`，保留 `published_at` 的历史含义，页面明确使用首次发布时间。到期停止公开应愿，已进入 matching 的心愿沿用现有履约规则，不在所选期限到期时中断匹配。

存量心愿保持原 `duration_days` 和 `expires_at`，不因增加90天选项批量延长；尚未首次公开的心愿保留原选择，作者可在发布前修改为1–90天。首次公开历史不可靠时保持空值并以既有最近上架时间显示，不伪造首次时间。已过期、撤下、完成的心愿不批量复活。

沿用 `duration_days` 字段，通过增量契约将服务端、数据库与客户端上限统一扩展为90；创建时省略仍为7天，显式0天、负数、非整数或超过90天均拒绝。旧客户端的1–30天请求继续兼容，编辑不得把已有60/90天静默改成默认值或截为30天。普通编辑不自动设置 `refresh_expiry`；现有显式刷新有效期操作保留，须由作者明确选择并确认后重审，成功重新上架时才按所选天数重算截止时间。列表和详情展示服务端实际截止日期。

### 编辑缺陷与修改影响

静态定位：`WishPond.vue` 的 allowed() 用 `items.includes(wish)` 检查对象引用；详情跳转后重新 getWish() 获得新对象，列表已有同ID时不替换，再传给 edit() 被静默拦截。修复时将读取结果按ID写回当前会话的列表，再用该对象进入编辑；仍校验资源版本、会话代次与服务端可操作项。权限变化或目标不可编辑时显示原因。此路径尚需本地真实接口复现确认。

沿用现有主体修改语义：保存修改会下架、使旧审核及未终结应愿申请失效，再提交审核；进入匹配后的普通编辑继续受限。编辑保存前明确说明影响，存在申请时展示受影响数量并确认。允许只进入表单/取消而不改变状态。轻量新增信息使用“作者补充”，不改主帖版本、不失效申请。申请失效后的站内通知也需补齐，避免申请者误以为仍在等待。

## 照片、身份与页面展示

### 最多三张照片

发布与编辑区支持0–3张图片、排序、删除、失败重试和预览。建议首版 JPG/PNG，每张规范化后不超过4 MiB，服务端另限原图尺寸及解码像素量；具体上限通过图片适配验证后写入契约，不能只靠客户端判断。客户端先压缩，后端检查真实格式、移除EXIF等元数据；不接收任意外部图片URL作为附件。

上传得到本人资源引用 `image_ids`；服务端在保存完整内容的事务里校验归属、顺序、张数、扫描状态和清理状态。正文与图片绑定同一心愿内容版本，全部通过才可公开。换图必重审；上传完成不等于已发布。上传中允许保存可恢复的页面草稿，提交发布需等待所有选中图片上传成功。

复用现有图片处理、审核供应商和私有对象存储，新建独立心愿资源命名空间。图片经受控读取接口展示，权限复用正文的 public/own/participant 边界，禁止把私有对象键或永久公开地址放入响应；被下架后普通旁观者新读取立即拒绝，已匹配参与者在现有规则允许读取正文时仍可查看对应图片，隐私/治理屏障继续优先。作者待审预览和审核员预览走各自授权入口。未引用、失败、替换和注销图片通过持久任务回收，审核证据与普通附件分别遵循现有清理边界。

### 作者与半匿名

建议心愿提供“公开署名”和“半匿名”两种发布方式，并在提交前预览实际公开效果：

| 模式 | 展示内容 | 主页入口 |
| --- | --- | --- |
| 公开署名 | 当前可公开头像、昵称、公开展示ID，以及勾选的标签 | 可进入现有公开主页，仅展示当前可公开内容 |
| 半匿名 | 默认头像、该心愿内稳定的匿名编号、明确勾选的校区/年级/性别；允许只选校区 | 不暴露真实账号ID、固定头像或真实主页入口 |

“展示ID”是平台公开编号，不是学号或OpenID。全局隐藏设置优先于帖子选项；未勾选字段不返回。半匿名编号按心愿上下文生成，回复、通知、分享、热点、收藏、搜索和公开主页都遵守同一投影，不能通过旁路关联真实作者；主页也不能列出该作者的半匿名心愿。已知本人判断和举报/屏蔽操作改用服务端能力字段及 opaque 引用，不能继续依赖公开账号ID比较。

身份模式在首次公开后锁定，草稿阶段可切换；既有公开署名帖子不能通过编辑承诺追溯匿名，需要另发半匿名心愿。同一心愿ID关联的还愿故事、故事列表、分享及后台公开素材导出必须继承其公开身份边界，不能在完成阶段重新公开账号关联。匹配双方按既有业务规则获得的参与者权限单独管理，不扩大到公共主页或匿名公开投影。

这是对“半匿名”的隐私保护型解释。若实际只希望隐藏部分标签、仍显示个人主页，应将该功能命名为“选择公开资料”，并另行调整本条规则，不能同时承诺匿名与真实主页跳转。悄悄话半匿名同步放宽为非空的允许字段子集，保留已有帖子内匿名隔离规则。

### 列表与详情

心愿卡片展示标题、摘要、首图、到期日期及“应愿N · 评论N · 小眼睛N”，保留现有支持入口。详情顺序为作者区 → 发布时间/截止时间 → 正文与图片 → 作者补充 → 评论区 → 主要操作。信息用低对比文字，主操作使用实色按钮，次操作用描边/图标，减少整页按钮并列。

公开投影统一返回 `first_published_at`、`published_at`、`expires_at`、`application_count`、`comment_count`、`view_count`、`favorited` 和受控作者/图片信息。申请数按当前内容版本审核通过、仍有效的申请计算；评论数仅含当前可见普通一级评论与回复，作者补充独立计数。聚合与列表查询批量完成，不能每张卡片再请求多个统计接口。

## 评论、楼中楼与作者补充

心愿新增评论；悄悄话在现有表及审核链上扩展，避免迁移重建其匿名和隐私数据。前端共享两层评论组件，后端共享基础工具，领域权限与生命周期仍分别管理。

- 根评论与楼内回复最多显示两层；回复楼内某人继续放在同一楼，显示“回复某匿名名/昵称”，不无限缩进。
- 请求提供 `root_comment_id`、`reply_to_comment_id`，被回复人由服务端解析；禁止传入账号ID指定接收者。服务端检查同帖、同根、当前父正文版本及目标仍可见，拒绝循环或跨帖引用。
- 根评论按公开时间稳定分页；每楼预览少量回复，“展开更多”独立分页。已有悄悄话评论回填为根评论，保留ID、正文、审核和通知历史。
- 心愿新增互动资格沿用悄悄话普通评论：有效、未受禁言/封禁的学生会话可评论；发心愿仍需认证。普通评论和回复建议最多500字，全部先审后见，失败可修改或撤回。
- 作者补充用根评论的 `kind=author_supplement`，仅帖主可发，展示于正文下独立区。首版仅展示补充本身，不在该区再开一套回复楼；讨论进入普通评论区。补充也需审核，不更改主帖期限与应愿申请。
- 普通作者回复带“帖主”标识。可见性、匿名和违规处理优先于帖主标识，不能为了标识回传真实作者ID。
- 保留悄悄话评论开关，并为心愿提供相同开关：关闭后禁止新增与未完成批准，已公开评论可只读。主帖改稿后的旧版本评论不自动挂到新正文下；主帖不可公开时，评论入口不能单独公开历史正文。
- 用户撤回根评论时可保留无正文、无身份的占位，展示仍符合规则的楼内回复；治理、隐私或危机隔离时隐藏受影响楼及引用上下文。回复目标不可见时不保留其旧昵称/原文摘录。

根评论首次公开通知帖主；楼内回复通知被回复人，并在需要时通知帖主。接收人相同时只发一次，本人不通知，审核重放不重复发。事件唯一键采用“事件+接收人”，同步调整现有仅按评论事件唯一的悄悄话通知约束。通知存引用和通用提示，打开时重新检查目标权限。

## 收藏、浏览量与未读数

### 收藏

三类详情增加收藏按钮，“我的”增加“我的收藏”，按心愿/悄悄话/资料筛选，按收藏时间倒序分页。收藏只对本人可见，不通知作者，本期不新增公开收藏总数。收藏保存目标引用，不复制标题、正文或下载地址。

PUT设置已收藏，DELETE设置未收藏，重复请求可安全重试，保留既有命令幂等机制；客户端对同一目标串行发送状态变更，防止快速连点的乱序回写。设置收藏需有当前目标读取资格；取消本人收藏不依赖目标仍存在。失效项显示“内容已不可查看”并可移除，不暴露旧摘要。资料收藏始终要求现有认证读取权限，不能经聚合页向游客泄露资料内容。

### 小眼睛浏览量

统一为“有效详情打开次数”，不是独立访客数、支持数或热度分。新进入详情并成功读取可见内容计一次；列表渲染、预加载、回前台、刷新、作者编辑和后台查看不计数。每次页面实例生成事件ID，网络重试不重复累计；新打开可以再次计数。保留现有限流。

新增轻量记录入口与原子聚合计数，事件去重仅保留短期技术键，不记录长期学生阅读轨迹。读取详情与上报失败解耦；计数失败不能阻断阅读。心愿旧详情事件可回填历史基线；悄悄话和资料从上线开始累计，不推测历史。列表批量返回计数，计数改变不递增正文/编辑版本。

新客户端使用统一事件入口，不同时发送旧心愿 `view=1`；旧入口保留兼容并更新相同计数，避免双计数。本期不改变现有热度排序/周榜公式，浏览量展示与排行榜语义分别验证。

### “我的”未读角标

新增全站通知汇总接口，返回权威 `unread_count`，与通知列表共用可见性、抑制及当前会话规则。不能把当前已加载分页的未读项数量当总数，也不能重复累加通用通知和悄悄话通知。

统一Pinia状态驱动底部“我的”图标右上角：0不显示，1–99显示数字，超过显示99+。登录/回前台/标记已读后刷新，前台有界低频轮询，后台停止；退出、换号即时清空，旧会话响应丢弃。角标表示站内通知未读，不另加聊天消息数；现有聊天通知已在全站通知中。通知标记已读后按当前汇总核对，不能直接把角标清零。

## 五年本科、词库与操作反馈

五年本科先补 `undergraduate_5 / 大五` 到权威年级选项，并验证个人资料、半匿名标签、包分配资料与新报名快照、管理端展示。沿用入学年份、学历层级和手动年级覆盖，9月1日切学年；不根据本科第5年推断已毕业，不重写历史报名。如果需要专门记录“四年制/五年制”，再增独立学制字段；当前需求先解决五年学生可选择、可正确展示。

词库继续使用现有内置与自定义词库、版本发布、试跑、停用、历史恢复。增加运营分类及显式缩写/变体、匹配边界与正反例样本；运营分类与普通/涉校/危机审核路由分开。普通网络用语、一般负面情绪建议提示或人工复核，明确攻击按普通违规处理，危机表达沿用现有危机路由。不能把“消极”一律自动驳回。对短拼音缩写使用显式词条及边界/上下文，不全量汉字转拼音匹配；允许当前自定义词条在新版配置中选择 hint/review，旧词条继续原处置。

管理端保留草稿 → 试跑 → 发布 → 历史恢复流程，展示命中字段、范围、规则版本和处置。新增网络用语词条需先验证正常讨论、引用、求助表达和英文词片段等反例。默认不重扫历史帖子；真实本地库当前词条在实施时只读盘点后准备增量。

小程序复用 AppNotice，改为居中短提示：建议成功1.5秒、信息2秒、警告/错误3秒、结果未知4秒；加载状态由当前动作控制结束，不自动误报成功。错误、未知结果在页面保留说明和原请求重试，悬浮提示消失不清业务状态。单一中心位置展示，重复消息合并；页面跳转后成功提示能被目标页显示一次。分别使用“草稿已保存”“已提交，审核通过后自动发布”“发布成功”“收藏成功”等真实结果文案，不把已受理称为已发布；后台轮询不刷成功提示。

引导复用 EntryPrompts：标题与说明卡片、页码/进度、独立底部操作区，主按钮实色、次按钮弱化；清晰区分解释文本和可点击动作。覆盖深浅主题、窄屏、胶囊安全区、键盘及长错误文本。管理端本轮只补新业务操作反馈，不同步缩短既有后台通知时长。

开发库使用可识别的本轮夹具，保留现有业务；普通启动不隐式迁移。后端按规则执行相关包检查、真实数据库/持久任务集成及交付前 make fmt/check/build；小程序 npm run check 和微信构建；管理端 pnpm format/check/build；docs检查链接、固定指纹及适用契约。

部署顺序为兼容的增量迁移 → API与受影响worker → 管理端 → 小程序，新增能力分阶段启用。数据库回退优先关闭新增入口并保留数据，不对已产生新数据的表直接破坏性回滚；解除数量上限后也不能回退旧后端，否则已有超过3条的数据会重新遭遇旧额度逻辑。图片/匿名新内容启用后，回退版本必须保留读取权限和隐私兼容。

实施已进入本地开发库与三端联调；实际完成范围及当前检查结果写入三端现状。本地接口/浏览器通过与微信真机、真实图片审核供应商及生产验收分别记录，不能互相替代。
