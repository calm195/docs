# 安全、隐私及恢复设计

版本v0.2，2026-10-16。依据G1基线v0.2、G2方案B。所有技术控制为本次设计，不代表已部署/验证，也不代替G3批准。受保护对象、删除例外、处置角色沿用基线，不因安全设计扩大永久保留范围。

## 1. 信任边界与威胁（REQ-002、007、008、014–020）

| 边界/威胁 | 控制 |
| --- | --- |
| 客户端伪造认证/角色/心愿状态 | 服务端会话＋PostgreSQL当前资格，字段白名单、对象级授权、所有命令事务复核 |
| 枚举学号/学生卡/他人私聊 | 公开投影不含身份，随机ID，越权404/403，案件和认证场景限定，DB角色隔离 |
| 拉黑/处罚/注销与审核或同意并发 | architecture.md锁协议；取消代次、精确内容版本和最终执行复核，旧任务不得复活 |
| 身份或危机明文进入DB/日志/对象/CDN | 应用层加密、敏感流No-Store、不公开对象URL、日志不采正文，密钥与备份隔离 |
| MQ/Redis保留已注销信息 | 不存正文/身份，最小技术ID、有限保留，消费者仅引用当前工作状态，注销删普通关联 |
| 恢复旧备份绕过注销/超管删证据 | 独立删除日志、恢复网络隔离、重删并验证后开放；日志不可作为非涉案永久审计 |
| 内部角色滥用 | 后台独立身份、最小角色、案件字段投影、完整资料访问留迹及非涉案注销清理；不提供全站私聊浏览 |

## 2. 身份与会话（REQ-002、014、016、018、019）

小程序通过微信临时code交换平台身份，AppSecret仅在服务端密钥源；学号和学生卡人工审核解锁学生权限。微信身份本身不等于在读认证；不引入原文未要求的手机密码业务登录。后台账号与学生账号分离，首个超管由部署初始化流程线下配置，后续超管管角色，不公开注册。

API采用随机高熵不透明会话令牌，数据库仅存摘要；每次查账号生命周期、处罚与auth_epoch。学生客户端依平台能力保存令牌，不存完整学生卡/学号/危机正文；后台优先令牌仅内存，必要续期走受控HttpOnly/Secure凭据并验证Origin/CSRF，不把浏览器localStorage作为私密资料缓存。具体会话时长/续期参数部署前锁定并测试，不假设模板演示令牌有效。

登录、身份审核、危机/证据读取及后台角色变更使用单独限流与告警；超管敏感删除采用再次验证当前身份及明确理由，不能只因按钮可见执行。后台是否接统一身份提供方/MFA可在部署能力确认时增强；此为安全建议，不捏造现成外部账号能力。

## 3. 角色及敏感字段矩阵（REQ-002、007、017–019）

| 数据/动作 | 普通用户 | 审核运营 | 危机人员 | 超管 |
| --- | --- | --- | --- | --- |
| 公开昵称、未隐藏标签、上架心愿/已审故事 | 当前可见时可读 | 可读公开投影 | 同左 | 同左 |
| 普通私聊 | 原双方且账号未注销；待审只发送者可见本人状态 | 仅普通命中案件中的消息，不能任意浏览 | 仅属于危机案件的必要内容 | 可按明确管理场景访问，不以全部权限自动开放无目的全量导出 |
| 完整学生卡、姓名、学号 | 不经普通资料API回显 | 仅身份审核场景，并记录访问 | 非认证审核角色，不可看普通学生卡 | 明确审核/管理场景可见并留迹 |
| 危机事件完整学号及内容 | 仅本人依法可读的普通视图，不开放后台案件 | 无完整危机身份权限 | 案件级可读 | 可读 |
| 普通违规举报及处罚/申诉 | 本人举报/处罚/申诉的允许视图 | 可受理、处罚/申诉，身份仍按脱敏 | 可受理、处罚/申诉；不因此获得普通认证审核权限 | 全部 |
| 解除危机误报 | 不可 | 不可 | 可，回普通审核 | 可 |
| 后台账号/角色及永久证据删除 | 不可 | 不可 | 不可删除永久证据 | 可，有明确理由与恢复删除闭环 |

“全部权限”不等于前端常驻完整身份列表。完整字段解密必须在服务端授权之后，读卡接口校验当前案件和角色，响应No-Store且不写URL日志。普通角色获取同一对象的公开接口不能携带标记自行切换成完整字段。

## 4. 加密、索引与密钥（REQ-002、007、017、018）

设计采用经维护的标准库/SDK提供的认证加密，候选AES-256-GCM，逐次独立随机nonce，AAD绑定用途、随机对象ID及版本，禁止自造密码算法；实现前核验SDK及密钥服务支持，记录算法/密钥版本。每对象或受控粒度的数据密钥由独立主密钥包裹，数据库/对象仅存密文和wrapped key，密钥管理权限与备份读取权限分离。

加密覆盖身份字段、学生卡原图、危机内容及私聊正文；公开心愿/故事保留通过审核后的最小脱敏投影，原始敏感版本加密。云盘或对象服务端加密不能单独替代这一应用层控制。外部图片安全判定如需要原图，只由受限工作者临时解密向已核验接口传送，不落明文文件/日志，超时或失败保持待处理；实际服务可用性和数据处理边界待账号核验。

学号/OpenID查重用独立检索密钥HMAC，不能用可枚举明文学号索引或无盐摘要；检索键不是允许普通运营读取的脱敏字段。密钥轮换采用有界双版本读取及重加密，检索轮换需临时双代唯一映射和单一认证命令串行化，防止同学号不同代摘要各占一个账号。失去密钥时拒绝访问/新敏感写入，不降级明文；备份恢复必须能受控取回有效密钥，否则报告无法恢复而不伪造成功。

供应商/KMS、凭据注入方式与轮换周期尚待运行环境确认；选择不改变数据库/对象备份不能自带解密密钥的边界。密钥访问和后台操作留技术安全记录，不把已注销者普通身份写入永久日志。

## 5. 学生卡对象与上传（REQ-002、015、018、019）

首发普通业务不提供图片上传，仅学生卡入口。请求在服务端边界检查用途、认证会话、MIME及真实文件类型、大小和像素、解码安全；使用随机对象键，不嵌入姓名/学号。临时原图仅受控内存或加密临时区，完成/失败清除；图片安全扫描与学生资格审核分离，图片安全通过不自动认证。

候选技术防护参数：JPEG/PNG白名单、单文件5MiB及最大像素维度，具体维度/压缩策略实施前兼容真实学生卡并形成配置验收，不写成用户已确认业务限制。首发无OCR提取、无公有卡片URL、无普通图片库。

七牛私有空间需要授权下载；本设计增加服务端鉴权代理及应用层密文，浏览器拿到的不是可以绕过当前角色的原始签名URL。相关能力以[七牛私有资源下载文档](https://developer.qiniu.com/kodo/1656/download-private)为技术参考，实际加密、代理及生命周期配置均须实现后验证。备份、学生卡、证据分开前缀/权限域，不用业务桶生命周期误删永久证据。

## 6. 内容安全与数据副本（REQ-006–008、014–018）

文本先扫描再交付，普通词/涉校词/危机词按基线分流。扫描失败不可公开/送达；危机先隔离、建事件与关怀待办，再尝试外部通知。词库/审核样例、组合信息判定规则和举报类型由运营交付；模型/词库判定不是保证识别所有危机，也不承诺医学效果。

待审正文只在源表加密，审核任务/MQ/死信/站内提示不复制正文。普通违规私聊案件仅解密命中消息；拒绝“查看该用户所有聊天”的通用接口。普通消息取消/待审不自动升格为永久证据；只有已认定违规或已建危机事件的限定内容按案件保留。解除误报不绕过普通审核。

Redis不存普通正文/完整身份，前端不持久缓存卡/私聊敏感响应。API响应关闭共享正文缓存；分享仅存目标引用，访问重读当前权威状态。日志/错误追踪/APM禁采请求体和Authorization/Cookie、签名URL、SQL参数，采用路由模板+无身份标签的技术计数；发生泄漏需定向清理，不以日志通常保留为理由绕过注销。

## 7. 注销与证据删除（REQ-004、005、007、008、018）

注销使用本人有效会话及明确confirmation，禁言/封禁不阻止隐私处理；封禁日常仅申诉例外，注销入口为已确认隐私权技术入口，不赋其他业务权限。若账号主体无法验证则先身份核验，不让他人删除账号。

设计阶段清理协议：

1. 先在独立受限删除日志持久写随机job及删除意图；尚未推进时该意图已经禁止恢复系统重新开放此主体。无该日志持久确认，不对客户端返回注销已受理成功。
2. 业务事务锁主体及当前关系参与者，标记deleting、auth_epoch递增、撤销会话/取消待审；同事务对注销者关联的幸存内容写privacy_hold、递增屏障代次并失效旧公开审核，再按基线10.4六行矩阵终结关联和释放/保持额度；独立日志或业务事务任一步崩溃时恢复程序按删除意图继续，不回到可读状态。
3. 分批清理数据库普通行、学生卡及对象版本、通知关联、缓存和非涉案访问审计；清理期间所有普通接口已拒绝访问。应愿人注销保留许愿人自有内容但剔除其身份引用，相关公开故事在步骤2已保守隐藏，此步剔除引用并生成脱敏新版本重审；许愿人注销删除本人心愿和故事。
4. 证据仅保留限定涉事内容、当事学号、处理人/时间线及处置申诉；普通学生卡不因其他违规一并保留。普通关联删完后，移除账号guard/唯一占用，回执completed；任务失败保持processing并告警，不显示“已全部删除”。
5. 超管删证据使用相同的独立删除意图/外部对象清理/恢复屏障；不以“永久”拒绝已确认的超管删除，不因超管删除让原普通业务重新出现。

删除日志是恢复所需受限技术标记，不是永久保存非涉案审计的例外。仅存随机实体/对象标识、删除范围、技术序号/时间及完成状态，无学号/内容/浏览行为；旧备份中仍可关联标识，因此按敏感技术元数据加密隔离，不声称不可重识别。全部可恢复副本窗口及过时事件失效窗口已覆盖且演练证实后清理标记，不无限保存。

## 8. 90天备份与恢复闸口（REQ-018）

普通数据库、私有对象和证据域备份都受有限90天备份周期约束；证据主存储可永久保留，但备份不无限累加。WAL、快照、对象历史版本、托管服务回收站及运维导出均计入可恢复副本清单；不能只给一个数据库定时文件配置90天就宣称满足要求。

恢复顺序为：隔离网络且关闭消费者外发→受控恢复DB/对象/密钥版本→读取独立删除日志并核验覆盖范围与完整性→应用注销/证据删除并取消过时任务→清理Redis/会话，重建非敏感辅助状态→重建发件箱/消费者关系，禁止重放已取消工作→按六行矩阵/抽样对象/证据删除测试验证→明确运维放行后开放对外读取与消息发送。

若删除日志缺失、落后、完整性不明，保持隔离，不能先开放再补删；若密钥不可用，不能声称恢复完成。恢复流程无需虚构RPO/RTO，但不免除该闸口。删除日志本身需独立持久与访问控制/备份，保留只覆盖必要恢复窗口，不与业务同一次回滚丢失。

## 9. 运维权限、验证与剩余依赖（REQ-017–021）

数据库迁移账号、API普通账号、后台消费者账号、证据解密权限、备份恢复操作权限分开；API无超管运维凭据；密钥和云账号不放仓库、前端环境变量或业务日志。生产默认关闭模板Mock、无认证示例接口及默认演示口令，检查真实合法域名/HTTPS和错误输出。

安全验证必须覆盖：未认证/越权对象读、认证场景以外完整资料请求、普通运营危机访问、普通私聊任意搜索、旧版本批准、消息取消后重试、已注销身份旧token/旧图片句柄、超管删除副本及恢复后重删、90天窗口清理。实际运行未验证，不能把本设计当成通过证据。

运行时人工8–22时北京时间，夜间自动措施保持工作；无认证审核或危机首次响应SLA、暂不设可用性/RPO/RTO。待环境核验项为密钥服务/图片安全/微信能力/管理员登录方式与资源版本组合；未满足时暂停对应实现验收或上线，不重写已批准业务范围。


## 10. 本轮评审补强（AR-002–AR-004）

关联REQ-008、015、016、018、019。用户已授权采纳本轮报告建议及推荐数值，详细对应见 `../reviews/architecture-remediation.md`。

- **先屏蔽再清理：**注销事务把仍存活作者的相关故事/可能公开心愿内容写入privacy_holds，即使无法可靠识别正文中的身份也保守隐藏；屏障与主体deleting同提交。所有公开列表、详情、主页及分享都检查屏障，不只检查作者状态；原匹配/注销账号关联清除后，稳定内容ID上的屏障仍在。多次注销的所有hold须各被对应新版本审核覆盖，不由单个旧approved解除。
- **恢复不解除屏障：**重启、消费者重试、旧审核晚到不能释放hold；脱敏新版本同当前代次审核批准后才能按全部现有公开条件公开。恢复验证除账号删除外还检查幸存作者旧故事不可读。清理未完成期间普通用户不能借编辑接口原样导出屏障内容中的已注销身份；受控脱敏源仅清理/案件用途读取。
- **警告不是禁言：**轻微警告复用处罚表但action_kind=warning不参与mute/ban交互限制；30秒采用服务端首次display时点，客户端无法伪造已等待，重进不重置。警告移除的违规内容依然不可公开/送达，用户不因未确认warning获得该内容的例外读权。
- **提示与建议的安全：**涉校“未经证实”标记随版本输出，不能把标签当作未经人工批准可公开的理由；revision_suggestion不包含他人完整身份、敏感词命中上下文或审核凭据。案例访问和本人读审核结果仍按角色与对象关系授权。

验收反例：保留含应愿人可识别信息的已审故事，启动其注销并暂停清理，事务提交后的新读不得在任何公开入口得到旧正文；作者重审与注销并发时按相同内容/屏障版本拒旧结果；新脱敏版本通过前持续隐藏。轻微警告29秒ack拒绝、30秒成功、重复幂等，且不暂停无关应愿。均为设计验收条件，未执行产品测试。
