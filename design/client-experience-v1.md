## 页面清单规则

每条清单必须同时包含路由、页面/弹层、角色、状态、字段、动作、组件、接口和关闭条件。一个路由可以对应多个业务状态；“路由打开”不能关闭等待、配对、失败等独立状态。数据由既有服务端权限和领域状态决定，页面不能按设备时间猜测已发布结果。

独立HTML参考统一从[新版设计入口](client-design-index-v1.html)查看，包含六样板和各页面族代表。全量结构与分批顺序见[页面族设计](client-page-families-v1.md)。完整清单在[小程序页面清单](client-pages-miniprogram-v1.md)和[管理端页面清单](client-pages-admin-v1.md)。接口和环境依赖在[样板接口边界](client-sample-api-v1.md)。

### 样板一 包分配资料

顶部小标签“给未来的相遇”，标题“先从认识你开始”，说明“认真写下自己，也留一点空间给惊喜。”；下方三步导航“关于我 / 我的期待 / 确认资料”。

1. 关于我：年龄、身高、体重（斤），个人特质、介绍与可选微信号。资料身份字段只读展示；已有自动保存与错误恢复继续有效。
2. 我的期待：年龄/身高/体重范围，校区及MBTI多选，理想型特质。分类选中项及输入草稿跨步骤保留，不能因切换用途或分类清空。
3. 确认资料：按“我的资料 / 对方偏好 / 可见范围”汇总真实值；主操作保存。保存、待审、已生效、结果未知分别显示，重试保留原请求与幂等键。

个人特质和理想型分别按性格、兴趣、生活、待分类组织。两种用途各最多10个，每个1～20字。先选择分类，再选择推荐或添加新词；同名共享词条不能被用户覆写分类。审核结论与可否新选用分别展示；停用词条保留历史回显。

### 样板二 活动与配对结果

同一路由按真实状态展示不同主内容：未报名、待审、等待公布、已配对、已公布未配对、结束；驳回和撤回在报名状态内明确解释。顶部为简短信笺引导，不让插画遮挡时间和行动。

- 等待公布：状态标题、活动时间线、下一步说明；不显示匹配概率或虚构倒计时。
- 已配对：标题“这封来信，有了回音”，对象资料卡、双方已公开特质、有效聊天入口及每日任务。推荐分仍是推荐分，任务查看不改名为完成。
- 未配对：温和说明、资料入口与其他活动入口；只有后端确认结果已发布才能进入此态。
- 已结束：结束说明与可执行下一步，不返回或展示失效配对资料、聊天入口和任务。

### 样板三 心愿详情

作者与状态 → 标题/正文/图片 → 发布/截止信息及支持、应愿、评论、浏览统计 → 主操作 → 评论线程。原有收藏、分享、举报、撤回、编辑、应愿、还愿等按角色和状态保留可达入口。

评论保留顶层评论、楼内回复、回复对象、作者补充、本人待审/驳回记录、编辑撤回、分页及失败重试。评论读取失败不隐藏正文，不将待审核评论加入公开计数。长标题、长昵称和多图不能压缩统计至不可读。

微信组件重置使用显式样式类，检查编译后的WXSS；uni编译可能删除裸 `text` 标签的scoped规则。跨自定义组件的间距由显式属性或容器负责，不依赖父级 `> view:last-child` 选择器命中子组件根节点。折叠状态检查实际 `[hidden]` 行为，文本输入仍使用原生 `textarea/input`，不得以批量标签替换改变控件类型。375px为尺寸基准；430px另外核验rpx整数取整，不用额外补高度掩盖差异。

### 样板四 活动列表与独立详情

活动列表标题、说明、右侧“新建活动”；筛选区域和连续表格。服务端未提供的搜索不能伪装全量搜索。列表状态与翻页在进入详情后可恢复。

活动详情保留返回、标题、状态与主要操作，内容分“活动设置 / 报名审核 / 配对结果 / 每日任务”。自动分配继续区分生成、核对、应用草稿与发布，发布不能由前端本地修改状态代替。报名审核可见完整依据和必要理由。

### 样板五 内容详情与审核

列表定位内容后打开抽屉。抽屉顺序为可见统计、正文/图片、作者补充、评论/回复上下文和处置区；公开详情和审核案件沿用各自授权，不互借接口扩展敏感访问。审核理由、版本冲突、待确认原键重试始终可达。复杂关联流程可进入原独立页面，不强塞进抽屉。

### 样板六 特质管理

主操作新增词条；筛选按名称、用途、分类、审核状态、启停和已有热度条件组织。列表保留人数、词云、审核依据及原有统计；抽屉查看/审核/归类，编辑时使用读取版本。审核通过与启用分别处理，待审词不进入公开推荐。关闭抽屉不丢失未知写请求。

## 对照方法与阶段边界

独立设计参考见[页面设计参考](client-experience-v1.html)，由协调者先按上述规格制作；业务组件由两端独立实现。参考使用显式合成文案，不调用业务API。实际样板用本轮重置后的开发库真实API及合成账号，不拦截业务请求冒充联调。

| 维度 | 核对方法 | 样板关闭条件 |
| --- | --- | --- |
| 结构 | 相同视口、内容、业务状态，逐项核对区块和主次操作顺序 | 无遗漏字段、入口或错误层级 |
| 几何 | 小程序对齐内容区，管理端对齐壳体；量取主要区块边界、间距、字号和圆角 | 同渲染环境关键锚点偏差不超过4 CSS px；跨微信/浏览器系统字体差异单列，不能掩盖错位 |
| 状态 | 真实数据切换、空态/失败/无权限、长内容及结果未知 | 每个状态都有实测结果；测试替身仅用于无法稳定制造的传输异常，单独标注 |
| 交互 | 步骤前后、草稿恢复、分类新增、审核、评论回复、抽屉焦点和列表返回 | 真实API变更并重新读取确认；原请求重试不换键 |
| 平台 | 小程序微信开发者工具，管理端浏览器；双主题及不同宽度 | 无遮挡、横向撑开或不可达操作；H5不替代微信 |

样板有明显差异时先修样板，不批量改其他页面。样板关闭后按包分配→心愿/悄悄话→个人/消息→资料/胶囊→其余管理模块推进。每个批次复用通过核对的组件与标记，不复制孤立样式，不仅凭路由数量宣称完成。

各端检查、真实API、微信模拟器、手机和生产分别记录在三端现状/缺陷/计划中。自动化或AI检查不签发G1/G2/G3；手机真机、真实微信身份及生产发布需各自实际证据。
