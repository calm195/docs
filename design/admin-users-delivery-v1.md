## 2. 相对v1.1的落地细化

1. 详情增加 `account_version`，解决处罚目标版本来源；不是新业务动作。只读源码证据：后端 `internal/safety/commands.go` 将penalty命令期望目标绑定command.Account，将appeal_decision绑定command.Appeal；管理端 `src/composables/useSafety.ts` 目前将人工accountVersion作为普通处罚expected_version。两端本次实施须接入详情版本、避免猜值。
2. `allowed_actions` 固定为三种导航提示，不把原写动作混进用户页动作枚举；新增写操作为零。
3. 处罚历史用安全摘要替代直接解密自由理由；普通案件之外的来源不在用户页返回可反查匿名作品的链接。危机记录按原权限过滤；详情全局限制状态不暴露不可见处罚的ID/数量。
4. 明确50码点搜索、ASCII大小写语义、White_Space集合、30分钟游标、错误码、null和排序，避免两端各自解释。Wire与细则以本包为固定输入；这些是设计细化，不改已确认首期范围。
5. 后端事实快照：`develop` / `5d6fcd614edb8e048677d8bc9813a790b632f0ac`；管理端：`develop` / `69f07a2af4c84b4da8026c636c7a06463491f548`。读取时两源码工作区干净；只读定位不能证明HTTP/数据库/浏览器运行通过，启动源码开发前必须重新检查漂移。
