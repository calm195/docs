# 包分配自动配对方案对比

本轮交付只改变报名资料来源，运营继续审核、手工确认配对并发布。自动配对以离线方案对比作为交付，后续若启用，第一步只生成配对草稿。

## 候选与评分

先过滤未通过活动审核、当前学生资格失效、处于交互限制、已占用、报名版本已变化以及任一方向拉黑的组合。样本沿用现有男女分组条件，跨校区仍是有效组合。同校区目前加 25 分，跨校区加 12.5 分，任一方缺少人格标签时人格项给 18 分。年龄、身高、体重使用双方区间。按上线前的匿名样本对比去掉校区项、人格项和现有规则后，分别统计配对组数、跨校区比例、分数变化及落单原因。

当前推荐是逐人查看，优先分数，再按已有确定性顺序。批量方案应使用与推荐一致的候选资格及版本，在写草稿和发布时重新校验。若要更改异性分组，需先确定产品规则，允许任意兼容组合时需要一般图匹配算法。

## 小样本对照

以下分数为手工构造的测试输入，用来隔离分配算法与评分模型。B 与 Y 有硬限制，其他组合可参与。C 与 Z 是彼此唯一的可行组合。

| 候选 | X | Y | Z |
| --- | ---: | ---: | ---: |
| A | 98 | 92 | 无候选 |
| B | 90 | 无候选 | 无候选 |
| C | 无候选 | 无候选 | 88 |

| 方案 | 样本结果 | 适用条件 |
| --- | --- | --- |
| 人工推荐 | 从 A 开始选最高分得到 2 组、186 分。管理员识别 B 的唯一候选后，可调整到 3 组、270 分 | 活动人数少、需人工权衡 |
| 全局贪心 | 分数降序选择 A–X、C–Z，得到 2 组、186 分，B 与 Y 落单 | 实现简单，可作性能及结果基线 |
| 最大基数、同基数最大权匹配 | 选 A–Y、B–X、C–Z，得到 3 组、270 分，最低配对分 88 | 当前候选是二分图，可用最小费用最大流等方法 |

比较规则先最大化配对组数，再在同组数方案中最大化总分。上线前还需确定是否存在最低可接受分数，并在求解前过滤低于门槛的边。总分相同时按固定报名标识顺序决胜，避免同一快照重算时结果漂移。人工锁定的草稿先占用两侧名额。输出应区分「无合格候选」「候选已被其他配对占用」「管理员锁定」等原因。

若采用批配，先做只读预览，记录活动版本、候选快照版本及规则版本。确认时在现有活动事务内一次写入草稿，版本冲突后重新预览。评估使用小规模样本验证最优性和同分稳定性，再用满额活动验证计算时延和数据库锁持有时间。
