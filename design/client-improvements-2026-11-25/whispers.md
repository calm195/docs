# 悄悄话 · 页面与数据设计

[打开列表原型](whispers.html#feed) · [打开一条心事的详情](whispers.html#detail/library)

原型从悄悄话列表进入。点击第一张卡片的抱抱、分享或标题，可分别体验行内操作、好友卡片回流和详情收藏。进入“我的心事”，打开“晚跑时遇到的那阵风”再编辑，可看到之前保存的标题、正文和仅公开校区的配置。从“写心事”选择半匿名，可比较首次预填与编辑回显。进入“暖评身份”选择半匿名，关闭一项并保存，再打开“写暖评”可检查新评论实际沿用的身份。另有未认证账号示例。样例数据仅在页面内存中变化。

## 两个缺陷有同一个数据来源

| 入口 | 当前 develop 工作区行为 | 拟调整 |
| --- | --- | --- |
| 我的心事 | `whisperOwnPostsList` 循环调用 `ownerPost`。已公开帖也进入正文遮蔽分支，返回 `title/body/identity_input=null`。页面将空标题显示为“未命名悄悄话”，空正文没有摘要。 | 修正本人投影后，列表优先使用当前版本真实标题，将可读正文折叠两行。长标题最多两行，保留状态、审核意见与详情入口。 |
| 本人详情 → 编辑，以及编辑页携带帖子 ID | 两个入口都用 `whisperOwnPostGet`。编辑器 `accept()` 将上述三个空值分别变为空标题、空正文、完全匿名。已公开帖仍可能有更新动作，因此能打开空表单。 | 统一通过本人详情回填，明确区分新建、加载中、可编辑及不可读取。完整快照到达之后才可输入或保存，任何字段因屏障遮蔽时转为状态视图。 |
| 公开列表 | 通用 `WhisperContent` 先输出署名和“帖主”，再输出标签，最后才是标题。帖子作者身份与“当前读者就是作者”在接口中使用不同字段。 | 标题右侧依据 `viewer_is_author` 展示。本人帖子只标“帖主”，他人的帖子仅列已公开的身份标签。 |
| 详情 | 正式页面已有帖子标题、抱抱、写暖评及评论计数。上一版原型重复显示标题，遗漏详情抱抱，并把收藏放在暖评区标题旁。 | 页面使用具体的帖子标题。正文卡底部同一行放抱抱、评论数和收藏，下方保留暖评与回复及写暖评入口。 |

## 本人读取与版本兼容

1. 在 `ownerPost` 的本人校验和 `postState` 判定之后，对正常 `published` 且 `published_content_version=current_content_version` 的当前版本走可读分支，从该版本的 `title_cipher/body_cipher/identity_cipher` 取作者保存值。私有接口只返回当前本人。公众、分享及分享回流继续取已审公开投影。比较测试使用原稿与公开脱敏文字不同的样本。
2. `privacy_hold/isolated/restricted` 继续输出三个空值，列表显示对应业务状态，不拼接正文，不用公开详情或缓存恢复旧稿。其他人请求本人帖子返回 404。源数据读取失败提示重试并关闭保存，便于区分数据错误和真实空标题。
3. 早期版本没有标题密文时，保留已有服务端“未命名悄悄话”兼容值及可读正文摘要。当时未填写的标题无法还原。若旧版本以该文本为合法标题，原样显示。数据修复无需批量改写帖子或迁移历史稿。
4. 列表与编辑沿用现有本人响应形状，首版仅在 UI 取两行摘要，避免逐卡再查详情。编辑只读本人详情，按 `id+content_version+version` 装载当前标题、正文、档位、已选标签和昵称版本。局部刷新保护尚未保存的输入。切账号、切帖或屏障生效时清掉前一份缓存。未修改就保存不应触发已公开帖下架。
5. 将用户变更与“配置已过期”分开。历史年级停用、旧昵称撤销或被更换时，显示原选择和业务提示。有更新动作的稿件由本人重选后再保存。旧稿只选校区时，即使现在个人资料多了年级和性别，编辑也只勾选原校区。发生版本冲突先检查服务端状态，仍可读才在内存保留输入，由本人决定重新编辑。超时未知沿用原键原体。
6. 已公开帖发生实质修改时在保存前明确提醒“保存后，这条心事和原评论将暂时撤下”。保存只生成草稿，提交审核是独立动作。保留原资源版本、内容版本、评论代次与审核语义。

实现和兼容依据见 [版本写入](../../../liyuanci-backend-go/internal/modules/whisper/commands.go)、[读取屏障](../../../liyuanci-backend-go/internal/modules/whisper/repository.go) 及 [标题增量契约](../../contracts/whispers-v1-r2/README.md)。

## 半匿名取值与逐项选择

建议默认使用已通过学生认证的账号资料。当前认证申请核验姓名、学号和卡片，服务端没有“认证通过的校区／性别／年级”三个审核字段。半匿名界面使用“来自个人资料”，学生认证只决定发帖资格。若业务要求每项标签均由学校核验，须另行定义字段采集、审核与来源，不能把本方案的个人资料标为学校核验。

| 候选 | 首次切换半匿名时的来源 | 无值、过时或隐藏 |
| --- | --- | --- |
| 校区 | 本人 `GET /api/v1/me` 的 `identity_tags.campus`，仅接收树洞已有三个有效校区 | “不限”、缺值不选中，提示可到个人资料补充 |
| 年级 | 同一响应中服务端按入学年份、学历、手动设置或旧标签产生的 `identity_tags.grade`，与树洞当前年级字典匹配 | 值缺失或失效时仅该项不可选。整个树洞字典不可用时依现行规则停用半匿名 |
| 性别 | 本人资料 `identity_tags.gender` 的明确公开值 | 缺失、“保密”默认关闭。不做任何推断 |

新帖初始保留完全匿名。用户主动选择半匿名时，把有效候选逐项带入并勾选，提供实时“公开预览”。同一份草稿切换档位后再切回，应保留本次开关。关掉一项即从提交的 `identity.tags` 中移除。若全部关闭，显示“保留至少一项，或使用完全匿名”及切换入口。保存前允许查看全部已选标签。开启全局“隐藏身份标签”时预览和公开读取均隐藏标签，已存稿逐项选择保留。新帖先展示“当前已隐藏”，由用户决定是否调整全局偏好。缺少全部可用候选提供“使用完全匿名”和补充资料路径。公开投影仅用已审本帖快照和当前隐藏设置，资料更新不回写其他帖子。帖子正文和编辑草稿只驻留内存。

写入继续使用 `identity={mode:"semi",dictionary_version,tags:{…}}`。固定版 `whispers-v1-r2` 的 `Tags.required` 列出三项，当前小程序的增量契约用 `anyOf` 约束“至少一项”。服务端 `tagsValid` 接受任意非空合法子集。实施时将该语义及三个单项、组合、全空的样例同步到新版本契约与消费者。保持老版三项输入兼容，禁止伪填隐藏字段以满足旧定义。新增默认值及逐项开关应用于写心事和设置页的评论身份。

### 评论身份设置与暖评回显

- “悄悄话设置 → 身份与昵称 → 评论身份”继续沿用本机账号偏好。已认证账号首次主动切换至半匿名且没有已存半匿名选择时，预填上述可用资料。已有偏好优先回显原模式和选中的项目，关闭的项目不会因资料补全而自动打开。切换模式再切回保留本次选择，点击“保存评论身份”生效，离开而没有保存时使用之前的偏好。
- 沿用 `readCommentIdentityPreference/saveCommentIdentityPreference` 按 API 环境和账号隔离保存模式、已选标签及字典或昵称版本。只保存用户主动选择的评论身份配置。新暖评或新回复展开时读取快照，输入框旁显示“本条暖评身份”和公开预览。收藏、帖子编辑等操作不改评论偏好。调整偏好后，下一条新暖评使用新快照。历史暖评继续使用自己的身份版本。
- 首次无偏好默认完全匿名。字典或昵称已失效、偏好损坏时，现有读取逻辑降为完全匿名并显示重新确认提示。已发出的未知结果请求继续使用原键、原请求体。全局隐藏作用于暖评的实际公开展示，保留本人已存选择。
- 登录但尚未通过学生认证的读者仍可依据帖子 `allowed_actions` 发暖评。完全匿名、已审树洞昵称及以前已保存的合法半匿名配置仍可使用。首次主动选择半匿名可沿用现有受控自选项目，不自动把资料当作认证结果。游客点击评论仍走登录，已关闭评论或无写动作时只读。评论设置独立于发帖的学生认证条件。

参见 [评论身份设置](../../../liyuanci-miniprogram-uniapp/src/pages/whispers/settings.vue)、[本机偏好](../../../liyuanci-miniprogram-uniapp/src/utils/whisper-comment-preference.ts)、[新暖评与编辑取值](../../../liyuanci-miniprogram-uniapp/src/composables/use-whisper-comment-editor.ts) 和 [运行中的标签扩展规则](../../../liyuanci-miniprogram-uniapp/src/utils/whispers-contract-extensions.ts)。

## 卡片、分享与详情

- 列表卡片从标题开始。若 `viewer_is_author=true`，标题右侧只显示“帖主”。否则只渲染当前公开响应 `identity.tags` 中可见的校区、年级、性别。完全匿名、全局隐藏或仅有树洞昵称且无标签时，标题使用整行。署名 `identity.label` 留在详情呈现。评论里的 `identity.is_author` 表示该评论是否由帖主发表，不能用它判断读者是否为本人。
- 长标题可折行，多项标签在标题右侧换行。正文摘要两行，涉校提示单独出现。
- 底栏从左至右为抱抱、暖评、浏览数、分享。按钮与正文导航用独立点击区域，按下抱抱只更新本帖。沿用 `PUT /api/v1/whispers/posts/{post_id}/hugs` 的显式目标态、预期帖子／抱抱版本、幂等键。按权威回执重绘图标与计数，确认失败回到原态，慢请求防连点，超时提供原请求重试。帖主自己和无动作权限者只读计数，游客可通过登录入口恢复合法动作。
- 列表分享使用微信好友卡片。按钮携带当前行的帖子 ID，页面 `onShareAppMessage` 仅针对本次按钮事件生成 `/pages/whispers/detail?id=<post_id>&shared=1`，菜单入口继续走品牌分享。复用品牌封面，卡片标题固定为“鲤愿池 · 一条悄悄话”，卡片不嵌入发帖人、标题、原文、身份标签或管理参数。本次建议按该帖的公开可读资格提供单帖分享，游客、未认证和已认证读者看到同一公开卡片时都能分享。当前心愿／故事分享适配器对已认证会话的限制属于原有两种内容。给悄悄话新增独立的列表目标处理。分享给另一条帖子的动作按新按钮 ID 生成。
- 接收方按 ID 调用公开 `whisperPostGet`，执行与正常公开访问相同的权限和屏障判断。撤回、改稿、删除或不可见时只呈现“这条心事暂时无法查看”及返回列表入口。好友发送和取消由微信完成，无可靠回执时不提示“分享成功”。通用品牌入口保留。既有 `ShareKind` 和带码海报接口仅支持心愿／故事，本次单帖好友分享不扩充海报接口。
- 详情页主标题取当前可读帖子的标题，只显示一次。正文卡底部从左到右显示“抱抱 N”“评论 N”，最右为“收藏／已收藏”。详情与列表共享同帖抱抱状态。自己的帖子只显示抱抱数。收藏沿用 `FavoriteButton` 的登录、切换与未知结果重试，热区至少 44×44 CSS 像素。
- 点击“评论 N”进入本帖的“暖评与回复”区域。允许评论时，该区域标题右侧提供“写暖评”，点击后在原位展开输入框。已关闭评论时仍可阅读公开暖评。提交待审只反馈给发送者，审核通过后才更新公开条数。不可见的帖子显示状态页，隐去原题和公开互动。

现有实现见 [列表抱抱](../../../liyuanci-miniprogram-uniapp/src/composables/use-whisper-feed.ts)、[内容分享适配](../../../liyuanci-miniprogram-uniapp/src/composables/use-content-share.ts) 和 [收藏](../../../liyuanci-miniprogram-uniapp/src/components/FavoriteButton.vue)。

## 交付顺序与验收

| 顺序 | 实施与可检查的完成条件 |
| --- | --- |
| 1 · 本人数据 | 在本地开发库用两个合成账号建立带标题、换行、表情和半匿名快照的草稿 → 送审 → 已公开样本。本人列表可见真实标题和两行摘要，两条编辑入口都还原原稿及已选项。另一账号无法访问本人详情。分别验证真实旧无标题、草稿、驳回、撤回、限制、隔离及隐私屏障。涉及安全状态时本人结果为空且不可编辑。 |
| 2 · 身份编辑 | 覆盖候选齐全、部分缺失、全空、年级过期、全局隐藏、完全匿名、已审昵称、历史半匿名及换账号。新建只在主动切换时填入。编辑先还原原稿。保存后重进、送审与公开详情逐字段对照，已关字段不出现在公开数据、UI 和分享预览中。旧版客户端提交的有效标签仍可读。评论设置只留一个标签后保存，在下一条暖评和回复中确认同一快照。旧暖评身份不变。用两个账号切换验证本机隔离。未认证账号可用完全匿名或已有合法半匿名配置写暖评。 |
| 3 · 列表与详情 | 用甲、乙两个读者查看同一条帖子。甲是作者时标题右侧只有“帖主”，乙只看到甲在该帖公开的标签。无公开标签时右侧留空。打开详情核对主标题只出现一次。从列表点亮再到详情取消抱抱，核对两处计数同步。打开暖评、提交后观察待审提示，关闭评论时已有内容仍可读。在 320px 宽度检查收藏与正文底部评论数同排且靠最右，切换收藏后不影响抱抱和评论。 |
| 4 · 真机分享 | 在微信开发者工具检查编译后的按钮事件与卡片路径，再用两个微信账号实测连续分享 A、B 两帖、落地与返回、对方无会话、取消、分享后撤回。普通菜单仍到品牌入口，单帖按钮精确落本帖。失效内容不泄露旧摘要。原型“查看接收页面”仅为流程预览。 |

本次已在本地 Chrome 的 320、390、1280 像素宽度走查离线原型，验证抱抱切换、按帖分享回流、详情收藏、已公开帖回填、新帖半匿名预填、关闭单项、修改后撤下、草稿提交及失效链接页面。评论原型逐项关闭至仅剩校区后保存，另一条心事的新暖评正确沿用该单项。未认证账号使用各自的已有配置及完全匿名完成模拟送审。三种宽度均无整页横向溢出。数据库场景、真实微信分享与业务端到端回归列为实施后的验收项。
