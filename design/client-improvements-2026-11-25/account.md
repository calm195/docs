# 头像昵称、认证图片与通知浮窗

从「我的 → 个人资料与隐私」或个人页顶部的头像昵称进入编辑。从「我的 → 身份认证」进入学生卡续办。以下是基于 2026-11-25 develop 工作区的设计提案。原型中的照片是插画和虚构卡面，原生微信选择、网络和审核回执用本地交互模拟。

[个人资料原型](account.html#profile) · [身份认证原型](account.html#verification) · [通知浮窗原型](account.html#notices)

## 个人资料

**现状。** 小程序设置页已有相册、拍照、恢复默认头像和手写昵称。自选图片校验成功会立即上传。昵称所在的资料表单支持自动保存和手动保存。头像上传和资料更新各自校验账号版本，并各有幂等键。当前设置页的关键落点是 `src/pages/settings/index.vue` 的 `chooseAvatar`、`changeAvatar`、`saveProfile`，请求分别在 `src/api/avatar.ts`、`src/api/settings.ts`。[现行头像上传契约](../../contracts/avatar.v0.2.1-r2.md)

| 入口 | 预览与保存 | 取消或失败 |
| --- | --- | --- |
| 使用微信头像和昵称 | 一个入口打开资料面板。用户点「选择微信头像」，在昵称栏点选微信键盘建议或直接输入，可仅改一项。「使用所选资料」带回预览，「保存资料」写入。 | 取消选择保留原值。组件未返回头像时不清原图。昵称为空提示重填。旧基础库隐藏不支持的选项，提供自选头像与手填昵称。 |
| 系统随机头像和昵称 | 从随小程序发布、已获使用权的 JPG/PNG 图集和校园昵称词组抽一对，避开刚展示的组合。可换一组或单独改昵称。选择期间仅改草稿。 | 返回或取消不改账号记录。保存沿用现有尺寸、图片审核、昵称长度与服务端审查。候选不写入用户真实身份字段。 |
| 自选头像、恢复默认头像 | 保留相册、相机与恢复默认。将当前选图后的自动上传改为统一预览，提交时只写本次变更。默认头像沿用删除头像命令。 | 原生选图令页面临时隐藏时保留待选状态。切账号或退出清理草稿。 |

微信基础库从 2.21.2 支持头像昵称填写。头像通过 `button open-type="chooseAvatar"` 取用户选择后的临时路径。昵称通过 `input type="nickname"` 接收用户在键盘上选中的值。2.24.4 起图片检查未通过时可能没有头像回调，昵称失焦后的异步检测也可能清空输入。实现用微信支持的 form submit 读取最终昵称，再做 1–40 字校验。联调要验证候选昵称未经手动改字直接提交。原型使用按钮代替系统键盘推荐项。[微信开放文档 · 头像昵称填写](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/userProfile.html)

**与现有自动保存的衔接。** 微信选取或随机生成的组合先保存在面板内部。预览、取消、离页和普通字段的自动保存都不能写出未确认的候选。保留原表单对其他字段的自动保存，点击「保存资料」时合并已确认的选择，串行执行需要的命令。若另一个保存正在进行，先等它的回执并取得新版本。

**保存协议。** 沿用 `POST /me/avatar`、`DELETE /me/avatar` 和 `PUT /me/profile`，本文接口路径均省略 `/api/v1`。从小程序包中选择的预设图先转换成可供现有上传流程读取的文件，保留后端审核。不接收客户端提供的远程头像 URL。头像变更先保存，使用成功回执的新 `version` 保存昵称及原表单已编辑字段。若只有昵称变化就只写资料。若只有头像变化就只写头像。每一步独立保留输入、版本、幂等键和结果。头像成功而昵称失败时显示「头像已保存，昵称待保存」和重试入口，只重试未确认步骤。遇到版本冲突先取最新资料，保留用户编辑，重新确认后保存。两步均完成再显示「资料已保存」。

## 身份认证续办

**现状。** `src/pages/verification/index.vue` 在正常隐藏和卸载时调用 `clearPrivateData`，清除 `asset`、预览临时路径、姓名和学号。重新进入只恢复人工审核记录。再次选图会先清空旧回执。「移除」当前只改内存。后端 `internal/httpapi/student_card.go` 提供上传和按已知 ID 查询，`studentcard.Asset` 仅含 `asset_id, scan_status`。安全扫描 worker 已持久化资产状态与对象版本。后台审核员可经受控接口读图，学生侧缺按账号恢复与本人预览入口。[现行扫描结果语义](../../contracts/decisions.v0.2.0.md) · [学生卡保护设计](../security.md)

| 进入页面时的状态 | 用户看到什么 | 可以做什么 |
| --- | --- | --- |
| 首次，无可用图片 | 学生卡上传入口、姓名与学号 | 上传后可离开。服务受理前取消选图维持原状。 |
| 候选正在扫描 | 「新照片正在扫描」，若有旧图仍显示其扫描记录 | 离开后从服务器恢复同一候选。停留时有界轮询。扫描超时显示「重新查询」。有旧图时可选择「取消替换，继续使用原照片」，然后提交旧图。 |
| 已扫描通过，尚未提交 | 已保存的卡面入口、通过状态与扫描时间 | 查看原图和记录、替换、填写信息并提交。离开后不保存姓名学号。再次进入直接使用已通过的图片。 |
| 替换未通过或处理暂不可用 | 原可用图及原结果。候选拒绝或待处理信息 | 明确拒绝后可继续用旧图或重选。处理暂不可用只提示重查。上传及扫描中的候选不自动带用旧回执。 |
| 人工审核中、已通过、已驳回 | 申请进度、结果或驳回原因 | 待审及通过不改已提交材料。驳回重提时可恢复本人仍可用的旧图、核对或替换，按已读审核版本提交。 |

**拟议数据与接口。**

1. 以 PostgreSQL 保存每个账号的认证草稿，主键为账号 ID，包含 `active_asset_id`、`candidate_asset_id`、`revision`。资产表继续记录对象及安全状态，追加可空 `scanned_at`。只引用本人的学生卡。首次启用时，若旧账号尚可申请，且有唯一、可证实仍有效的未绑定通过资产，可安全关联。多张历史图无法判断意图则提示重新选择。已驳回且允许重提时可从当次案件的有效资产恢复。旧记录缺少实际扫描时间则仅显示「已通过」，不以创建时间代替。迁移按上线时的连续版本追加。
2. 新增 `GET /me/verification-draft`。对当前学生返回 `{revision, active, candidate}`，两字段可为 `null`。每项只含资产 ID、扫描状态和可用的扫描时间。空草稿返回 200 和空项。401 去登录，503 原位重试。读取人工审核申请仍用既有接口，分别呈现图片扫描和人工审核状态。
3. 上传沿用 `POST /me/student-card-assets` 与幂等键，在同一事务写入新资产、处理任务和候选指针。新客户端提供草稿版本前置条件（例如 `If-Match`）。旧客户端仍可按既有 API 上传查状态。上传、替换、移除及提交统一按账号锁序复核版本，重放已确认请求不再次改指针。worker 完成时写真实扫描结束时间，只允许仍为当前候选的资产晋升。扫描通过原子替换 `active`。失败保留原图和候选失败状态。旧扫描晚到仅记原资产结果。旧客户端仍可提交原契约允许的有效本人资产，新客户端提交另带草稿版本前置条件。同一事务冻结审核材料并退出可编辑状态。遇到版本冲突重新读取草稿和审核记录。
4. 新增 `GET /me/student-card-assets/{id}/preview`，仅在认证办理场景为本人当前可用图提供 `image/png`。服务端鉴权后限量读取对象、解密，再复核会话、账号状态、草稿归属、资产版本和用途，记录受控访问后发送 `Cache-Control: no-store`。越权、已失效资产返回统一 404。微信端可通过带令牌的请求读取内存数据并在受控预览层显示，真机验证大图内存与销毁。前端不持久化原图、学号、对象键、永久链接或供应商扫描明细。
5. 为现有「移除」补上版本化的本人草稿解除关联命令，如 `DELETE /me/verification-draft/photo`。取消替换时用同一路径的 candidate 作用域，仅解除候选并递增草稿版本，扫描迟到不覆盖旧图。既有审核材料单独保留引用。替换或移除后，旧图退出草稿读图范围。清理未被案件引用的废弃密文和中间载荷，复核任务引用与账号生命周期。活跃可办理草稿保留当前通过记录到替换、移除或提交。如产品需要固定天数，再明确期限、到期提示与清理策略。用户注销接入现有 privacy/cleanup.go 的账号资产发现与删除链路，先清草稿引用，按所属私有对象版本回收。其他业务文件的 24 小时回收规则不直接套用于正在办理的学生卡。
6. `onShow` 先核实登录账号，再读草稿与审核记录。`onHide/onUnload` 继续清除姓名、学号、内存图像与计时器。请求按账号、会话代次、页面可见性与候选 ID 接受回执。首次提申请沿用既有规则，重提携带 `expected_version`。提交超时先核实当前申请，后续重试保留原请求及幂等键。若先前请求已受理，直接显示待审。

## 操作反馈

**现状。** `src/components/AppNoticeHost.vue` 将提示固定在屏幕中部。错误、警告与结果未知共用红色边线。`src/utils/notices.ts` 管理单条展示、重复去重、关闭及计时，`AppNotice.vue` 负责页面错误或未知结果的持续展示。调整主机的布局、图标及文案层级，保留现有动作与页面状态。

| 类型 | 原型中的消息 | 反馈规则 |
| --- | --- | --- |
| 成功 | 资料已保存 | 对勾、绿色。1.5 秒收起。 |
| 消息 | 学生卡已上传 | 信息图标、青色。2 秒收起。 |
| 进行中 | 正在检查图片 | 进度图标。可手动关闭，后台操作继续。终态替换进度。 |
| 提醒 | 请重新选择照片 | 感叹号、琥珀色。3 秒收起，相关操作留在原处。 |
| 失败 | 照片暂时无法查看 | 叉号、砖红色。3 秒收起，页面保留错误与重试。 |
| 结果待确认 | 保存结果待确认 | 问号、琥珀色。4 秒收起，页面提供「确认保存结果」。 |

提示距自定义导航栏及系统安全区下缘 8px，左右 12px，白底圆角 12px。图标、标题、可选短说明、右侧关闭组成一行。关闭热区至少 44×44 CSS px。正文可换行，长错误详情在原操作附近显示。仅浮窗本身可交互，其余区域允许滚动与输入。用文字和图标区分状态，浅深主题均核对对比度。新状态替换旧提示，后台轮询更新卡片、不反复播成功。单独关闭浮窗、切页、超时均不清业务错误、回执或原请求。

## 联调验收

- **头像昵称。** 用 iOS、Android 微信分别检查选择头像、原生键盘推荐、手填、取消、失焦校验和低基础库降级。微信与随机选项均先预览。只换昵称不上传头像，换一组不写库。同时更新读取新的版本。模拟第二步失败和网络超时，能看到部分成功且只重试对应命令。
- **认证续办。** 本地两个测试账号分别上传。甲在扫描中离开、杀进程、重新登录或换设备后，能读同一资产 ID 与服务端结果。通过后直接提交且无新上传/重扫。乙无法看到甲的草稿与图片。切换账号后旧响应无显示。刷新历史通过数据时缺失时间应隐藏。
- **替换及提交。** A 已通过时选择 B，取消或 B 失败后 A 可提交。B 通过后仅 B 可预览或作为新客户端的当前申请。覆盖并发替换与晚到回执、提交时另一设备替换、移除后旧句柄、注销后预览、扫描服务暂不可用、审核版本冲突、已受理但客户端超时。后台审核仍能只读当次材料。
- **浮窗与文案。** 六类反馈在 320/375/430px、小程序系统胶囊和大字号/深色模式下可读，可手动关闭，关闭按钮有读屏名称。检验同一动作重试、后台轮询、跨页返回、旧计时器及失败/未知的原地重试。正式配置下复核认证页、个人资料页、登录弹层、错误与空态的实际可见文字。

以上是实现验收条件。离线原型演示材料选取、重新进入、扫描结果、替换、查看和提交。微信原生组件、真实扫描服务、敏感图片预览和后端并发均需在实现后验证。
