## 实施顺序与交付物

| 顺序 | 工作包与依赖 | 可以转入下一步的条件 |
| --- | --- | --- |
| 1 · 准备数据与复核缺陷 | 用本地开发库的专用示例账号建立有标题的已公开帖、历史无显式标题帖、受屏障帖，以及本人/他人已扫描图片。记录当前接口与工作区已有改动。梳理管理端各过滤器的数据源 | 同一条已公开帖可沿“我的心事 → 编辑”核对两处字段。能区分旧数据缺标题与当前投影隐藏标题 |
| 2 · 悄悄话 | 修复本人列表与详情读取，编辑只在成功取得可编辑版本后启动。同步调整卡片、抱抱、分享与详情收藏。新增半匿名资料默认值和逐项开关 | 作者能安全改稿，他人和被屏障记录不能读。既有帖子保留原选择，分享失效帖时不返回旧内容 |
| 2 · 资料与认证 | 完成本人认证草稿查询、私有预览、替换和清理，再接小程序续办。头像昵称选择接入原生填写、现有审核与版本机制。通知浮窗和文案可提前完成 | 跨页、冷启动、换号、替换失败、并发提交均有确定结果，图片通过和人工认证通过可清楚区分 |
| 2 · 管理端 | 先交付导航、搜索调度和统一分页外观。已有总量和完整本地数据的页面先接入，其余逐项补齐页码查询和同条件计数 | 每个有分页的列表都能验证第 1 页、末页、直跳、清空筛选和数量减少后的回退 |
| 3 · 本地联合验收 | 合并兼容的服务端能力后接两端，联调所需 API 和 worker 使用同一套本地数据。管理端用不同岗位，小程序用两个独立账号 | 下节场景通过，业务结果从服务端独立读取。微信输入、分享、键盘和安全区在设备上复验 |

实施优先扩展响应或增加版本化能力，先交付服务端、再开启依赖它的页面。需要新表或索引时按实施当日账本选迁移号，验证旧行、空库和新旧客户端并行读写。若回退界面，保留已完成的认证申请、在用认证材料的归属、帖子的可见性屏障和现行数据。后端在缺少新展示能力时仍执行权限、版本、审核和清理规则。

## 联合验收脚本

1. **从列表进入同一条帖子。** 用甲号发表有标题、正文和半匿名标签的帖子。甲在列表看到“帖主”，乙在同一位置看到甲公开的标签。乙在列表点亮抱抱，进入详情核对实际标题、取消抱抱、查看评论、提交暖评，并在评论数所在行最右端收藏。甲从“我的心事”核对摘要、原稿和身份开关。甲保存改稿后，乙重开旧分享卡片时应看不到撤下的内容。
2. **离开后继续认证。** 甲号上传材料 A，扫描通过后关页、重启、重新进入，核对记录并预览。换为 B，分别验证取消、扫描失败与通过。另一账号读不到 A 或 B，已提交的人工申请仍引用提交时的版本，材料失效、清理和离线均有可理解的反馈。
3. **确认昵称头像。** 分别测试微信头像/昵称都选、只选一项、取消、昵称安全校验后被清空，以及系统随机、重新生成、确认保存和网络中断。重新进入以服务端保存值核对资料。身份认证材料不出现在普通头像或分享预览中。
4. **在后台找到同一批数据。** 从深层菜单进入长列表，进行中文输入、快速增删条件、调整每页条数、跳到末页并制造末页记录减少。与服务端同权限筛选的条数比对。切换角色或离开页面后，上一条件的迟到响应不应露出数据。
5. **核对视觉与提示。** 小程序在 320–430 CSS 像素、深浅色、微信安全区与字号放大情况下检查卡片、浮窗和操作热区。管理端分别用桌面、窄屏和键盘验证侧栏滚动、父子项、焦点、筛选、跳页及错误恢复。按文案清单复查正式模式及模拟模式。

## 评审采用的产品口径

- 微信资料采用一个入口，头像和昵称按微信提供的交互分别由本人确认。系统随机头像昵称允许重新生成并预览。
- 通过扫描的照片按本人账号恢复，持续可用到替换、移除或提交。提交后按人工审核申请的材料规则管理，注销时进入既有清理流程。材料留存及替换规则见[资料与认证方案](account.md)。
- 半匿名取已认证账号可用的本人资料，用户选择半匿名并确认逐项公开后写入本帖版本。现行认证采集姓名、学号和学生卡。校区、性别等自填值应注明来源。若要求这些字段也经人工逐项认证，需扩展认证采集与审核范围。[悄悄话方案](whispers.md)
- 列表分享按“将所点的公开帖子发给微信好友”设计。能查看该公开帖的读者均可从列表转发，卡片用通用封面与文字，接收端重新校验当时的可见性。后台任意跳页按完整筛选结果设计，真实计数由数据源提供。[悄悄话方案](whispers.md) · [管理端方案](admin.md)
