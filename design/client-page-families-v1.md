# 全路由页面族设计与落地顺序 v1

日期：2026-11-16。依据[页面与组件设计](client-experience-v1.md)及[小程序清单](client-pages-miniprogram-v1.md)、[管理端清单](client-pages-admin-v1.md)。本文件是全量页面的结构设计；逐页实施与验证状态只记入三端滚动文档，不把设计建议写成已完成。

样板通过实际浏览器与微信开发者工具对照后，按以下页面族推进。每批先确认该族独立参考及完整字段，再使用已验证组件落地；新增接口另发契约，已有权限和未知写入恢复保持。

## 小程序

### 共同规则与可复用结构

- 外壳继续用 AppPage、原生子页导航及主页面 AppTabBar。通过明确属性控制32rpx内容边距，不能依赖全局 `.field`、`.page text`、Tailwind的隐含尺寸。安全区和底部栏空间由外壳承担。
- 页面标题只出现一次；导航栏已有标题时，内容区标题表达当前任务或具体内容。全局正文与明暗主题保持现有 theme.ts，包分配信笺只在该模块使用。
- 内容卡32rpx内边距/圆角、块间24rpx；卡片承担一个信息组。列表行可以由连续分隔组成，不把每个字段做成卡片。
- 字号：内容大标题44rpx/1.35、区块标题32rpx/1.5、正文28rpx/1.6、辅助24rpx/1.6。输入框最小88rpx；数字/单位同一标签，标签不继承输入容器背景。正文/图片按实际内容增长。
- 页面一次突出一个当前主要行动；分享、举报、屏蔽、撤回等按上下文进入文字入口或更多操作。破坏性操作仍使用原确认、理由、资格与状态；不因收纳而隐藏不可恢复的待确认写入。
- 加载、空、读取失败、权限/资格变化分开。列表失败不能显示空列表结论；写入未知结果固定显示原请求重试，不把重新提交当作重试。
- 折叠保持模型和请求状态：采用v-show时给微信 `[hidden]` 明确display:none；敏感内容退出授权后清除，不仅隐藏。

| 建议结构 | 责任 | 实际集成点 | 避免 |
| --- | --- | --- | --- |
| 页面标题/说明组 | 简短说明当前任务，可放一个主要操作 | AppPage及页面局部标题 | 每张卡重复大标题；主标题与原生导航重复 |
| 内容作者组 | 头像、昵称、身份、状态，公开主页入口按权限 | ProfileAvatar、IdentityTags、WhisperIdentity | 把匿名身份连接到公开用户；把ID当主要标题 |
| 内容正文/元信息组 | 标题、正文、图片、发布时间/截止、必要类别与报答 | WishImages、WhisperContent、现有类型字典 | 仅显示正文而丢期限/报答/审核意见 |
| 统计与主操作组 | 四项统计与当前主要行为；次操作收纳 | ContentStats、WishSupportButton、FavoriteButton、ShareActions | 将统计缺失渲染为0；多个并列主按钮 |
| 表单字段/分组 | 明确label、值、单位、帮助、校验状态、连续分组 | 原表单/composable，MatchmakingForm作为尺寸依据 | 全局.field兼任卡片；跨步清草稿 |
| 列表行/折叠区 | 标题、摘要、辅助信息、状态；展开后读完整详情 | 原列表组件、CommentThread、MatchmakingActivitySummary | 使用card套card造成空间膨胀；同一行多层点击冲突 |
| 状态与原请求区 | 加载、失败、空态、资格、未知写入，明确下一步 | AppNotice、原page composable及pending命令 | 用统一空态掩盖失败；自动换幂等键 |

每批先做1张独立参考与1个实际组件样例，使用同一合成fixture内容，再扩展到该族。不要先批量替换CSS再补截图。功能清单、接口状态、视觉锚点、行为证据分别记录；手机真机、微信开发者工具、H5和生产始终分开。

## 管理端

### 已验证并可复用的底座

- `WorkspaceHeading`：26px/36px标题、13px说明、右侧一个主操作；窄屏标题和动作上下排列。
- `WorkspaceDrawer`：680px/窄屏全宽、固定头尾、中部滚动、焦点循环、Esc/回焦、提交中关闭限制。组件只承载布局；案件授权、操作幂等与版本仍由原 composable 处理。
- `experience-page / experience-panel / experience-table-panel / experience-filters`：显式页面作用域，32px内容边距、24px面板内部间距、12px圆角、64px普通表格行；长文本自然增高。
- `PublicationDetail`：公开互动统计、授权公开正文/图片/还愿、评论和作者补充；仅用于公开内容投影，不能作为未公开案件的敏感接口拼接器。
- 仍复用 `FloatingNotice / useOperationFeedback / BusinessToolbar / PageSizeSelect / LocalPagination / ContentImages / WordlistEvidence`。不把所有业务操作塞进一个通用CRUD组件，不改现有权限和命令协议。

### 组件抽取边界

1. **可统一外观，不能合并业务状态**：公开内容、普通审核、树洞审核、身份材料、举报与危机不能共用“任意详情JSON”组件。只共享标题/抽屉/面板/页脚容器，业务内容仍用现有强类型组件。
2. **简单维护采用抽屉**：分类、字典、举报类型、任务维护、账号角色。字段较多、文件上传、多版对比、草稿编辑继续独立页面/工作区。
3. **只在实际重复后抽通用筛选面板**：目前CSS和槽位足够；勿为了统一把已应用筛选快照、游标分页、数字分页和未知命令复用成同一控制器。
4. **表格列由每个页面声明**：普通行64px；最小宽度按字段设800~960px；长标题/理由自然增高。日期/状态/动作不被长名称挤碎。窄屏保留内滚与可访问动作。
5. **不加协议没有的按钮**：活动搜索/阶段过滤、处罚全量列表、匿名身份反查、后台账号启停、新增待办面板均不是本轮授权中“改样式”可以顺带添加的能力。

### 门槛通过后的建议批次

- 第一批：资料分类、举报类型、展示字典、任务库、后台账号、本人改密。先统一表格/维护表单的可复用结构，逐页保持真实角色与版本确认。
- 第二批：资料管理、身份审核/历史、公开悄悄话分支、树洞审核。重点验证文件/卡图/匿名边界、取消与未知命令。
- 第三批：举报/处罚/申诉、词库和模块说明。保留复杂编辑、试跑、版本及离页保护，不能以视觉验收替代操作链验收。
- 第四批：普通/树洞危机、证据删除与回执、工作台。需要各自独立设计参考和授权状态夹具；只在前面骨架稳定后推进。

每批先更新独立设计与对应路由映射，再实施、真实API浏览器验证、同数据截图及人工比对；每批差异/未验状态明确保留，不以某个样板的通过覆盖全部页面。

### 每页需要保留的验收证据

- 岗位菜单/直达路由/真实API三层权限；隐藏按钮不是授权证明。
- 真实初始/有数据/空结果、超长字段、深浅主题、1440桌面及390窄屏；接口异常注入和真实正常链分开写。
- 读取详情按需请求，关闭/撤权及时清理；处理中禁关；Esc与回焦。
- 版本冲突重新读取；未知结果持有原路径、方法、body和幂等键；翻页不更换未应用筛选口径。
- 发布/取消/删除/处罚/危机升级以原确认与回执为准，不因统一主按钮省略核对。
- 每批只运行必要新增行为测试、现有pnpm检查和build；本机浏览器实测不能冒充生产/物理设备验收。
