# 三端开发与 docs 协作指令

生效日期：2026-10-22（Asia/Shanghai）。关联 T001–T004 及后续实施任务、REQ-001、REQ-018、REQ-020；不新增业务需求，不改变已有审批或业务实现权限。统一规则见[文档规范](../governance/README.md)。

1. 开始前读开发工程及 docs 的 AGENTS、对应[后端](../development/backend/README.md)/[管理端](../development/admin/README.md)/[小程序](../development/miniprogram/README.md)索引、[实施计划](implementation-plan.md)、[进度](progress.md)、[阻塞](blockers.md)、[联调](integration-log.md)及[契约](../contracts/README.md)。历史记录不代替当前分支/完整 HEAD/status 核查。
2. 开发工程与 docs 同步准备同名 codex/<主题> 分支；保护已有修改，不切换其他会话工作区。并行任务用独立工作树。同一任务多端共享 docs 分支时各自写对应端目录，共享台账由协调者汇总。
3. 明确任务、REQ、契约版本、直接前置、范围和可测试验收。阻塞未解停止依赖它的工作；只能继续无依赖且已授权范围。需求、批准和固定设计不改写；契约疑问在 docs 对应端另建记录，后端依既有授权协调共享契约。
4. 开发工程不保留阶段产物。完成修改后运行该端 AGENTS 规定的检查，在 docs 对应端新增阶段/验证记录；旧固定文件不追加、不格式化。记录实现/未完成、取舍、真实/模拟边界、实际命令与结果，不沿用旧快照测试结果。
5. 提交须有授权；先提交开发工程，将完整提交号补入新 docs 记录后提交 docs，追加固定清单与端内索引。交接区分未提交、本端验证、真实联调、需求验收；未获授权不推送、部署或上线。
6. 集成方锁定三端提交、环境、契约及准入条件；失败由对应端修复并新增记录，协调者回写台账。G1/G2/G3 和发布由用户明确确认；不推断某次基础探针或合成检查等于完整业务闭环。

## 各端验证

- 后端：make fmt、make check；Go/依赖变更 make build；真实数据库、MQ、监控及启停变化按后端 AGENTS 追加专项检查。
- 管理端：pnpm format、pnpm check、pnpm build，根中英文 README 用法同步；阶段文档仅中文。
- 小程序：npm run check；格式失败 format 后完整复跑；页面/样式/依赖/构建变化再运行 npm run build:mp-weixin。
- docs：python3 scripts/check_documents.py；四仓库 git diff --check。
