# 跨端后续安排

## 内容治理与特质交互调整

依据[治理查询增量](../contracts/moderation-query.v1.md)先更新后端筛选与游标，再更新管理端查询栏；验证待审核默认值及全部模式跨页优先排序。依据[特质 v5](../contracts/matchmaking.v5.md)应用历史拒绝关系清理迁移后更新后端和小程序，验证驳回后移除、重新保存不回填，以及待审核标签状态。

## 心愿支持与热点榜单交付顺序

先显式应用 0024 迁移，再更新 API、管理端与小程序。使用同一组心愿和悄悄话验证支持、取消、支持排序、周榜 Top 10 和后台权限。见[心愿支持与后台热点协议](../contracts/wish-support-hot.v1.md)。

## 理想型特质交付顺序

先显式应用特质新增迁移，再更新后端接口与两端。依据[活动协议v4](../contracts/matchmaking.v4.md)，验证词条保存、命中待审核、审核后推荐与报名快照，以及性别/热度筛选下列表和词云一致；使用本地开发数据库增量联调，保留已有业务数据。生产发布和微信真机验收单独执行。

## 包分配活动交付顺序

依据[活动协议v2](../contracts/matchmaking.v2.md)，先显式应用0019至0022中尚未应用的迁移，再更新后端 API、内容与隐私清理 worker，随后发布管理端和小程序。运营配置活动、任务和模块说明，使用隔离双学生账号与审核运营账号完成报名、修改重审、人工配对、结果发布、任务与退出闭环。未解锁正文、重复占用、跨年日期、原请求重试和注销清理是必测边界。微信真机、生产环境和活动容量分别验收，具体结果记录在各端现状及缺陷中。

首版不导入旧数据。若另行迁移历史，先核对旧用户/报名两层身份映射，保留Taskids中的已分配任务和查看记录，异常数据单独处置；不能重算旧分数或重新随机分配任务冒充历史。应用回退保留新表数据，先停用活动入口并核对兼容性。

## 展示字典与操作通知交付顺序

先显式应用展示字典追加迁移，再更新提供字典读取与维护接口的后端，随后交付管理端和小程序。协议见[展示字典增量](../contracts/display-dictionaries.v0.2.1-r1.md)。使用同一组数据验证管理端改名、版本冲突、原请求重试及两端读取，确认未知和停用条目的展示不会改变权限或状态规则。

两端操作通知复用各自现有组件，按成功、警告、错误和结果未知设置时长；关闭或超时只清理展示，不清除业务错误、待确认请求和回执。逐页核对主动操作与后台轮询，补充窄屏、键盘和微信真机验收。目录调整保持路由与分享地址兼容，清理需核对动态入口和生成契约用途。

## 资料文件与登录改进交付顺序

先显式应用0015资料文件迁移，再更新API与隐私清理worker，然后交付管理端与小程序。契约见[体验版改进](../contracts/trial-improvements.v0.2.1-r2.md)。本地已按此顺序完成联调；目标环境仍按实际发布授权执行。微信下载域名、手机明暗导航和会话重启单独验收。

## 体验版交互更新顺序

2026-11-07，本轮实现位于三端 `develop` 工作区。数据契约见[体验版增量](../contracts/trial-experience.v0.2.1-r1.md)和[悄悄鲤新修订](../contracts/whispers-v1-r2/README.md)。先显式应用0011和0012增量迁移，再更新API与内容审核worker，随后更新管理端和小程序。完成模块说明配置发布、双账号权限和内容链回归后，执行iOS/Android真机、弱网、下拉与分享验收。当前工作区检查、临时数据库集成和H5检查的范围分别记在所属端现状。

| 4. 真机与体验 | 小程序双设备/弱网/双主题；管理端窄屏/键盘/错误恢复；后端配合异常注入 | 当前SHA下关键页面链及恢复路径通过；二维码、真实分享和下载单独验证 |
