# 跨端后续安排

更新：2026-10-30。这里只维护跨端依赖和验收顺序；具体问题、状态与任务归所属端，避免再复制进度、阻塞、联调三套台账。角色分工是建议，尚未指派个人或承诺完成日期。

| 阶段 | 协作安排 | 依赖与退出标准 |
| --- | --- | --- |
| 1. 补齐正式输入 | 后端协调供应商；运营/资料维护者交付援助、关怀、年级、举报类型和词库；小程序接收投稿二维码 | 正式版本、来源、核验与责任可追溯；可用性和缺失降级有结果。资源阻塞只停止依赖它的场景 |
| 2. 固定环境并回归核心链 | 后端提供同一版本API/worker与隔离账号；管理端按真实角色操作；小程序使用A/B登录及页面 | 认证→心愿→应愿→匹配→聊天→还愿/分享，树洞/昵称/暖评/抱抱/胶囊，用户处置与资料反馈逐链通过，覆盖拒绝/旧版本/重复提交 |
| 3. 安全与恢复专项 | 三端核对撤权/换号/晚到；后端与存储维护者执行并发、清理、独立恢复 | 危机内容不泄露；删除失败保持屏障；全副本回执、幸存内容重审、恢复前重删及90天适用边界可核验 |
| 4. 真机与体验 | 小程序双设备/弱网/双主题；管理端窄屏/键盘/错误恢复；后端配合异常注入 | 当前SHA下关键页面链及恢复路径通过；二维码、真实分享和下载单独验证 |
| 5. 容量与生产准入 | 后端/运维准备固定数据量、负载、监控、备份恢复；两端核对发布配置 | 依据REQ-021和正式环境记录结果；审批、安全和恢复要求齐备后，另依授权部署 |

执行1、2中不受资源缺口影响的子项可以并行。隐私恢复、真实通知与容量没有通过证据时，不能以局部业务成功替代整体准入。

- 后端：[缺陷BE-01～05](../development/backend/defects.md) · [执行计划](../development/backend/plan.md)
- 管理端：[缺口AD-01～04](../development/admin/defects.md) · [执行计划](../development/admin/plan.md)
- 小程序：[问题MP-01～08](../development/miniprogram/defects.md) · [执行计划](../development/miniprogram/plan.md)

每次任务完成更新所属端现状、删除或关闭已解决的开放问题、调整后续次序；记录源码SHA、实际环境、验证日期与真实/合成边界。原始日志与历史阶段内容由Git或外部测试制品追溯，不重新建立按日期堆积的文档目录。
