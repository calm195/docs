## 1. 目标、依据与当前边界

【事实】用户本次要求“编写悄悄话模块开发计划”。按[原始输入](../requirements/original.md)，“悄悄话”对应独立的悄悄鲤／树洞模块，包含三档匿名、文字／语音、暖评／抱抱、时空胶囊与解忧入口。现有心愿匹配后的临时匿名聊天属于REQ-007，不能作为悄悄鲤已完成的证据。

【事实】[需求基线](../requirements/baseline.md)中的REQ-009、REQ-010、REQ-011仍为延期，未来细则未确认；[G1](../approvals/G1.md)、[G2](../approvals/G2.md)、[G3](../approvals/G3.md)批准对象不包含本次扩展。此次计划编制不改变旧基线、固定设计、正式契约或审批记录，也不启动业务实现。

【建议】目标是形成“匿名表达→审核→树洞展示→受控互动→举报／关怀／隐私清理”的独立闭环。先完成文字版本，再增加互动；胶囊与语音分别作为可独立排期的扩展。沿用Go模块化单体、独立worker、PostgreSQL、Redis、RocketMQ、Vue管理端与uni-app小程序，不新增服务体系。

文中标记说明：**事实**为本次核对或已批准材料；**原文愿景**为尚未细化确认的产品输入；**建议**为本计划推荐方案；**假设**仅用于估算；**待确认**不能直接当成已批准实现规则。下文任务、接口与验收均属建议，确认后另发需求／设计增量及正式契约。

## 4. 技术方案与三端改造

### 4.1 后端：独立领域、复用基础

【建议】新增独立`whisper`领域，复用命令事务、加密、版本化内容、审核、持久任务及权限模块。帖子不依赖心愿、匹配或聊天记录，不创建虚假心愿承载树洞数据。

| 数据／能力 | 建议增量与不变式 |
| --- | --- |
| 帖子与不可变正文版本 | 保存作者内部引用、匿名模式、当前版本、公开版本及公开时间；原文加密，公开只读已审脱敏投影；正文与标签／昵称显示版本一起绑定 |
| 匿名映射／昵称版本 | 账号关联限内部服务使用；公开采用帖子内别名，固定昵称明确跨帖语义。普通接口、日志、游标、通知与统计不能泄漏内部映射 |
| 评论与抱抱 | 评论关联帖子及不可变内容版本；抱抱用数据库唯一约束保护`(post_id, actor_id)`；取消幂等，计数与记录同事务或可重建，不以Redis计数作为权威 |
| 公共治理 | 为帖子／评论扩展内容注册、审核／举报／危机类型、数据库CHECK约束、授权锁序、任务分派、后台过滤和前端校验。既有类型行为必须回归 |
| 隐私清理 | 更新注销发现图、公开屏障、匿名映射、通知／回执引用及外部副本清单；取消旧扫描、投递与解锁任务；恢复后先重删再开放读取 |
| 胶囊／音频 | 后续独立表与私有对象引用；胶囊解锁用持久定时任务，音频上传／转码／扫描分阶段并绑定当前版本，不复用学生卡上传授权 |

【建议状态模型】正文审核状态与业务状态分开。文字主链为草稿→待扫描／待人工→公开或驳回；扫描失败保持待处理，危机进入隔离；撤回、治理下线、注销屏障优先于批准。批准事务必须同时检查当前内容版本、账号资格／处罚、隐私屏障及作者仍希望公开；评论另查父帖版本／可见性、评论开关和双向限制。取消状态不因解除处罚、重开评论、worker重放而恢复。具体枚举由正式契约确定。

公开时间只在版本实际公开时确定，分页建议使用公开时间＋随机资源ID的稳定排序与签名游标；游标绑定路由、筛选和适用读取主体，失效／篡改返回明确错误。此处不使用聊天`delivery_seq`，也不以草稿创建时间当公开时间。页面清理和服务端当前可见性复核共同防止旧响应回填。

### 4.2 小程序

【建议】在现有首页增加树洞入口和最新内容区，提供树洞广场、文字编辑页、详情页、我的树洞记录；P2增加暖评编辑／列表与抱抱、评论开关，P3增加胶囊列表／编辑／解锁详情，P4在已具备媒体条件后增加录音与播放。

- 编辑前展示匿名模式的实际预览及关联范围，原文和敏感草稿不落本地持久存储；取消／返回时明确未保存影响。
- 我的记录区分待审、驳回、公开、撤回及不可用，展示原因／修改建议；客户端仅按当前服务端`allowed_actions`开放写入口。
- 帖子详情不链接到真实账号公开主页；举报／拉黑通过当前资源上下文执行。正文渲染为文本，避免内容注入。
- 复用会话代次、离页清理、重复游标检测和弱网结果不明处理；重试写入保留同一幂等键，不能因超时重新创建内容。树洞列表默认下拉刷新／分页，不照搬聊天3秒轮询。
- 发布页常驻解忧入口，展示经过核验的资料来源／版本。现有本人关怀卡接口不能直接充当公众援助目录；缺资料时明确暂不可用，不编造热线或预约地址。
- P1不增加“关闭评论”空功能按钮；P2启用后才展示相关操作。P4录音授权被拒、切后台中断、上传超时和音频销毁均需真机验证。

### 4.3 管理端

【建议】优先扩展现有内容审核、举报、危机、证据删除工作台，增加树洞内容类型和必要筛选，不另建一套权限体系。查询列表保持最小投影；普通审核详情只读被审精确版本，处理在独立抽屉进行，审核结果与实际公开结果分开显示。

普通运营不能通过树洞别名反查完整学号或遍历用户的所有匿名内容。危机人员按限定案件读取必要身份并留迹，超管证据删除沿用独立范围及回执。P3私密胶囊不进入普通帖子浏览，P4音频仅在当前案件授权下临时读取；播放地址、正文及身份不写浏览器存储。
