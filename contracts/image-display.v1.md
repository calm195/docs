# 图片展示增量协议 v1

依据用户2026-11-12“除了CDN分发，实现其他加速优化”的授权，继承[内容互动v1](content-interactions.v1.md)和[头像上传增量](avatar.v0.2.1-r2.md)。新增规格不改变上传、审核、原图归属和当前权限边界。

## 心愿图片读取

`GET /api/v1/wish-images/:id` 和 `GET /api/v1/admin/wish-images/:id` 增加可选查询参数 `variant`：

| 参数 | 响应 |
| --- | --- |
| 省略或空字符串 | 原有规范化PNG原图，旧客户端兼容 |
| `thumbnail` | 最长边720px的等比缩略图 |
| `preview` | 最长边1600px的等比展示图 |
| 其它值 | 拒绝无效输入，不接受任意尺寸 |

展示图不放大小图片，保留透明度；不透明照片可为JPEG，透明图片为PNG，客户端依据实际Content-Type处理。对于无需缩小且重新编码更大的图片，可以直接返回原有图片字节。图片列表字段仍为`id/url/position/scan_state`，原URL不变，客户端显式附加variant。

学生侧沿用wish_id和当前会话/游客规则，后台沿用case_id或wish_id的岗位与资源归属规则。原图和展示图均在读取前后检查可见性；下架、换图、隐私或治理屏障不能被缓存命中绕过。应用响应继续使用`Cache-Control: private, no-store`和`X-Content-Type-Options: nosniff`；公网外层可统一为`Cache-Control: no-store`，仍须禁止私有及共享缓存保存。客户端不跨会话或内容来源复用图片，账号切换、撤权及离页清除预览。

存量心愿原图不改写，展示图按需在服务端生成并以独立用途加密后短期保存在有界进程内缓存。缓存同时保存已校验的原图密文，不缓存数据库权限或公开性，不新增持久对象、数据库结构或清理任务。

## 头像

新上传头像仍接受既有JPEG/PNG格式、原字节/像素预算、审核、资料版本及幂等约束，展示对象等比缩到最长边256px并保留PNG编码；小图不放大。审核继续针对原规范化图片，学生卡的无损规范化策略不变。

幂等请求摘要仍使用原规范化图片，已存在的预约按其记录的对象摘要完成安装。既有头像不批量重写，旧头像仍沿用原短效地址和缓存限制，新尺寸在重新上传后生效。

## 发布与验证

后端先行，两端随后更新；无需新增数据库迁移或CDN配置。图片尺寸、体积、缓存与权限回归分别验证；合成样本的压缩率不能推算真实网络耗时，微信观察器、原生预览及后台视觉须另行验收。当前实现与测试边界见三端现状。
