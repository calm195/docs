# 公开内容发现与后台内容管理增量 0.2.1-r1

## 公开列表与周榜

`GET /api/v1/wishes`、`GET /api/v1/stories` 和 `GET /api/v1/whispers/posts` 接受可选 `sort=time|hot` 和 `keyword`。缺省按时间倒序。关键词去除首尾空白后最多 80 个 Unicode 码点，按字面匹配已审核的公开标题或正文。既有筛选条件可继续使用。使用新筛选或排序时从第一页读取。热度降序，同分按既有列表时间和 ID 倒序，使用返回的 `next_cursor` 继续分页。

心愿热度为有效应愿人数加公开详情打开次数。小程序每次新进入详情页时通过 `GET /api/v1/wishes/:id?view=1` 记录一次成功打开，同一访客多次进入各计一分。页面刷新、恢复显示和其他普通详情读取不计分。详情计分沿用公开详情的接口限流。还愿故事按当前有效的不同登录访客计数，排除作者，重复浏览不加分。悄悄话按有效抱抱和可见暖评合计。

`GET /api/v1/content/hot?kind=wish|whisper` 使用标准响应信封，`data.items` 为对应公开列表的投影。每类最多 10 条，只列出滚动最近 7 天有有效互动的当前可见内容。心愿取有效应愿的创建时间和详情的打开时间，悄悄话取当前抱抱点亮时间和可见暖评发布时间。迁移前缺少时间的抱抱只进入累计热度。首页各取同一榜单前 3 条。

## 管理端内容查询与导出

| 方法 | 路径 | 输入与结果 |
| --- | --- | --- |
| GET | `/api/v1/admin/content/{wishes,whispers}` | 接受 `keyword`、`state`、`from`、`until` 和 `cursor`。心愿另外接受 `requester` 和 `helper` 昵称筛选。日期为 RFC 3339，区间左闭右开。返回 `data.items`、`data.next_cursor` |
| GET | `/api/v1/admin/content/{wishes,whispers}/:id` | 心愿详情含双方昵称、状态和可公开故事素材。悄悄话详情含可公开正文与暖评，支持从 0 开始的 `comments_page`，每页 30 条 |
| POST | `/api/v1/admin/content/{wishes,whispers}/:id/export` | 请求体为空。返回 `data.markdown`，成功时记录访问审计 |

审核员与超级管理员可查询，超级管理员可导出。心愿草稿要求当前存在可公开的还愿故事。悄悄话草稿使用公开匿名署名，最多收录 250 条暖评，超出时在草稿标注。不可公开或已撤回的正文和内部身份信息不进入草稿。导出是本地下载素材，公众号发布仍由运营人员操作。

## 运行策略

公开读与后台导出使用独立限额，有效会话按账号分桶，匿名按可信来源地址分桶。超限为 `429 RATE_LIMITED`，携带 `Retry-After`。Redis 访问故障期间，公开读回源 PostgreSQL，导出返回 `503`。

Redis 仅保存默认公开首页和周榜的候选 ID、时间、分数。API 异步预热并周期补齐。公开状态变更后清理相关候选，后台异步发布和互动热度在短 TTL 内刷新。候选命中后仍复核当前可见性与正文。
