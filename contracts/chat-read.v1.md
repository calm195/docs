# 聊天摘要与本人阅读位置增量 v1

日期：2026-11-15。承接 [OpenAPI v0.2.1](openapi.v0.2.1.json) 和[读取者方向增量](chat-viewer.v0.2.1-r1.md)，保留原有固定输入。

## 本轮依据

用户要求聊天列表放大左上方标题，将“可聊天”替换为居右的最新消息和阅读状态，并明确选择“我是否已读（显示未读／已读）”；同时要求通知跳转图标与内容同行，跳转后自动已读。此增量描述本次实现，不代表生产发布或真机验收。

## 本人会话列表

`GET /api/v1/me/conversations` 的 `data.items[]` 增加：

| 字段 | 类型 | 语义 |
| --- | --- | --- |
| `latest_message` | object/null | 当前参与者可读的最大送达序号消息；无可见消息时为 null |
| `latest_message.body` | string | 至多前120个Unicode码点的正文，超过时追加省略号；仅展示摘要 |
| `latest_message.delivery_seq` | integer | 已送达消息序号，不使用提交或审核时间排序 |
| `latest_message.viewer_is_sender` | boolean | 当前读取者是否为发送者，不返回发送者账号 |
| `last_read_seq` | integer | 当前读取者已确认的最大阅读位置，无记录为0 |
| `has_unread` | boolean | 存在序号大于本人阅读位置、且由另一参与者发送的可见已送达消息 |

列表摘要与详情共用审核通过、最终送达和有效内容限制过滤；先验证参与者、账号存续、处罚以及包分配当前可读资格，再解密正文。通知列表仍不返回私聊正文。摘要、阅读位置与方向不得跨账号缓存；响应保持 `Cache-Control: no-store`。本人发送新消息不消除尚未阅读的对方消息。

`has_unread=true` 显示“未读”，false 显示“已读”；这是本人阅读状态，不是对方回执。无消息时显示“暂无消息”。旧服务端缺少这些字段时，客户端显示待同步状态，不猜测已读、不发新确认命令。

## 阅读确认

新增 `POST /api/v1/conversations/{id}/read`，需本人 Bearer 会话与 `Idempotency-Key`，请求只接受 `{"last_read_seq": 正整数}`。客户端仅在当前可见聊天页已展示消息、位于末端或主动查看最新时发送已加载末条序号；上翻时收到的新消息、后台响应及仅浏览列表不触发确认。

服务端沿用会话和双方账户的事务锁序，复核本人读取资格及目标序号为可见已送达消息。仅更新本人记录，位置只增不减；不修改会话版本、写入代次或对方记录。成功按统一 code=0 包装返回 `{"id": "会话标识", "last_read_seq": 当前本人位置}`。结果未知时复用同一键和序号；同键异参冲突，非参与者404、非法/未来/不可见序号400，鉴权及处罚沿用原错误语义。

读取列表和消息的 GET 均无已读副作用。已有消息不补造历史阅读事实；迁移后首次进入聊天并确认显示的位置，才建立本人记录。

## 通知跳转

沿用 `POST /api/v1/me/notifications/{id}/read` 的本人通知版本和幂等规则。图标保留可访问名称和服务端目标类型映射；导航成功后发起已读命令，原通知页隐藏不取消该确认。跳转失败、无目标或期间更换账号/会话不写入。已读通知可正常跳转但不重复写入。结果未知保留原键、版本以供返回后重试；冲突刷新后由用户确认。

通知已读与会话阅读位置相互独立，任一通知的已读不代表已经查看聊天正文；全站通知角标在确认成功后刷新。

## 持久化与交付边界

追加 `0031_conversation_reads`，以会话和阅读者组成主键，保存序号及更新时间，随会话或账号删除级联清理。不得改写旧迁移或自动迁移生产数据库。交付顺序为显式应用0031及配套服务端，再交付小程序；旧客户端可忽略新增字段。

本次自动化验证、源码版本及未交付边界见[后端现状](../development/backend/README.md)和[小程序现状](../development/miniprogram/README.md)。
