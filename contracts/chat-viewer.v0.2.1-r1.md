# 聊天读取者方向增量契约 v0.2.1-r1

日期：2026-10-29。关联 REQ-007、REQ-018；基于 [OpenAPI v0.2.1](openapi.v0.2.1.json) 的聊天已送达消息响应作兼容性增量说明。本文件不改写已固定 OpenAPI 或历史动作索引。

## 授权依据与状态

【用户明确要求】本轮用户要求“聊天改为对话式，静默更新防止页面跳动”，并授权修复后继续真实双账号三端回归。

【实现取舍】采用读取者视角布尔值识别本人气泡，不向匿名聊天客户端暴露发送者身份。当前为该授权的增量实现约定；源码尚未提交，真实回归结果记录于[本轮联调记录](../development/backend/milestones/2026-10-29-local-three-client-integration-r1.md)，本文件不表示全量验收或上线批准。

## 响应字段

接口：`GET /api/v1/conversations/{id}/messages`。成功响应中 `data.items[]` 的每条已送达消息增加：

| 字段 | 类型 | 新服务端语义 |
| --- | --- | --- |
| `viewer_is_sender` | boolean | 当前鉴权读取者是否为该条消息发送者；是为 `true`，否则为 `false`。 |

服务端完成会话参与者及读取权限校验后，以当前鉴权身份与消息发送者比较生成字段。不得使用客户端参数指定读取者，不得缓存或跨账号复用另一读取者的方向投影。

字段适用于全部已送达消息，包括新增字段前保存的历史消息和游标增量页；由读取时投影生成，不依赖历史记录回填。A、B 读取同一消息时，各自得到对应视角的布尔值。

响应不增加 `sender_id`、用户主页标识、OpenID、身份标签或可反推出发送者账号的标识。现有 `message_id`、`delivery_seq`、正文和时间字段语义不变。

## 客户端兼容与显示

新客户端接受字段缺省，以兼容旧服务端；缺省值只表示方向未知，不得根据消息正文、提交时间或送达序号猜测真实发送者。收到明确 `true` 时显示本人气泡，明确 `false` 时显示对方气泡。旧客户端可忽略新增字段。

该字段只用于呈现，不授予发送、举报或会话读取权限。待审发送回执仍独立于已送达时间线；方向字段不改变审核、幂等、`write_epoch` 或 `delivery_seq` 规则。

增量页按既有送达序号追加；空轮询保留当前消息列表与输入，用户上翻时不强制滚至最新。会话结束转只读时保留可读取历史，权限失效时仍按原约定清除受限内容。

## 可测试验收标准

1. A 发送、B 读取同一已送达消息：A 得到 `true`，B 得到 `false`；B 发送时方向反转。
2. 历史消息和后续增量消息均包含正确方向，不返回发送者身份字段。
3. 非参与者仍不能读取会话；切账号不沿用上一账号方向或正文。
4. 缺字段的旧响应仍能显示正文，客户端不把未知方向当成经服务端确认的身份事实。
5. 无新消息轮询不清空列表或输入；阅读历史时收到新消息保留位置，用户主动查看最新后跳转。

【验证边界】服务端、客户端自动检查与真实双账号 UI 结果分别以本轮实施记录为准，不将本契约的验收条目视作已经执行。
