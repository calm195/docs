# 展示字典增量协议

版本：0.2.1-r1。范围：三端共用的展示名称与顺序，管理端维护、后端保存、客户端读取。本增量不改变既有权限、状态流转、处罚规则或固定反馈统计字段。

## 数据与读取

`GET /api/v1/dictionaries` 无需登录，返回公开展示快照。`GET /api/v1/admin/dictionaries` 要求有效后台会话，供后台维护页面读取。成功响应沿用 `code: 0`、`data` 和请求标识，`data` 为：

```json
{
  "version": 1,
  "items": [
    {"type": "resource_feedback", "code": "valid", "label": "有用", "sort_order": 0, "enabled": true}
  ]
}
```

`version` 为整个快照的乐观锁版本。`type` 与 `code` 共同定位一个稳定条目；两者不可通过维护接口修改。停用条目仍在快照中返回，以便解释历史记录。公开快照不得携带操作者、审计详情及个人信息。

展示名称为1至80个Unicode字符，不含首尾空白、换行或制表符；排序为0至100000的整数。类型和系统代码最多80个ASCII字符，仅使用小写字母、数字与下划线。

## 维护

`PUT /api/v1/admin/dictionaries/{type}/{code}` 仅允许超级管理员；请求携带后台 Bearer 会话及 UUID 格式的 `Idempotency-Key`。

```json
{"expected_version": 1, "label": "有帮助", "sort_order": 10, "enabled": true}
```

成功返回更新后的完整快照。更新、版本递增和审计在同一事务完成。版本冲突后必须重新读取并核对，不覆盖他人的修改；结果无法确认时保留原请求体与幂等键重试。重复请求不得重复推进版本，重放可返回当前最新快照，不要求退回首次请求时的旧展示版本。

系统条目不提供任意新增、删除或改码。认证状态、账号限制及后台角色不得停用；可选展示项的停用不改变既有业务接口接受规则，不充当权限校验。

## 初始展示类型

| 类型 | 用途 |
| --- | --- |
| `resource_feedback` | 固定四类资料反馈名称 |
| `builtin_wordlist_label` | 内置词库供应商标签的中文展示名 |
| `verification_status` | 学生认证状态名称 |
| `restriction_status` | 账号限制状态名称 |
| `admin_role` | 后台岗位角色名称 |
| `wish_state` | 心愿生命周期状态名称 |
| `resource_status` | 资料草稿、上架及下架状态名称 |
| `whisper_review_status` | 树洞审核状态名称 |
| `whisper_report_status` | 树洞举报状态名称 |
| `whisper_crisis_status` | 树洞危机状态名称 |
| `whisper_delivery_status` | 树洞关怀投递状态名称 |

新增类型通过后续迁移和配套消费端交付。已有资料分类、举报类型及受控身份字典继续使用所属领域的数据源，不复制到展示字典表。

## 举报类型维护

举报类型使用现有 `report_types` 表作为业务权威，独立于固定展示代码。`GET /api/v1/admin/report-types` 要求有效后台会话，返回 `data: {version, items: [{code, label, published}]}`，包括停用项。`version` 与展示字典共用发布版本，跨页面修改同样可能产生版本冲突。

`PUT /api/v1/admin/report-types/{code}` 仅超级管理员可用，携带幂等键和 `{expected_version, label, published}`，创建或修改指定稳定代码，返回完整后台快照。不提供物理删除或改码；停用不破坏历史举报。普通学生只读接口及树洞可选类型只消费已发布项目。运行目录直接读取数据库中的已发布举报类型，不再要求运营修改后同步维护一份 YAML 列表。

举报类型维护接口接受1至32个ASCII字母、数字、下划线或连字符，受既有树洞提交契约的32字符上限约束，不沿用系统展示代码的80字符上限。

受控年级仍继承原匿名身份字典的来源和版本协议，不与展示字典的全局版本混用。

## 客户端与交付边界

客户端按快照版本更新缓存；服务地址改变后不得复用其他环境缓存。未知条目显示安全占位或稳定代码，不在两端再保存完整中文映射。历史记录可显示停用条目名称；依赖可选字典的提交在无法取得有效数据时应明确提示。

展示字典首次使用前须显式应用追加迁移，再发布配套 API，最后更新管理端和小程序。不得通过普通 API 启动隐式建表。本地验证与生产迁移、浏览器全流程和微信真机验收分开记录在三端现状。
