# 平台用户直接处置需求增量 v1.2

日期：2026-10-29。关联 REQ-022、REQ-016、REQ-018、REQ-019。前版[用户管理需求v1.1](admin-users-v1.1.md)保持固定；本版仅替换与直接账号处置冲突的范围条款，昵称查询、隐私与原案件流程继续有效。

## 用户指令

本会话用户要求：“用户操作提供封禁/解封，禁言/取消禁言操作”。对“直接在用户页执行，还是沿用案件/申诉流程”的问题，用户选择：“直接管理（推荐）：填写理由后执行，新增后端接口与契约”。这是本次新增直接处置及两端实施的授权，不代表AI签发G1/G2/G3，也不自动包含提交、推送、部署或生产操作。

## 范围与可测试标准

| 编号 | 要求 | 验收标准 |
| --- | --- | --- |
| 022-I | 用户页提供封禁/解封、禁言/取消禁言；均要求理由和二次确认，不要求先有违规案件或申诉 | 正常用户可封禁或禁言；受限用户可解除对应类型；空理由不提交；请求不携带虚构案件 |
| 022-J | 封禁持续至解除，禁言沿用168小时；两种限制分别管理 | 并存时解封仍禁言，取消禁言仍封禁；解除对应类型的全部当前有效处罚；不影响另一类型、危机隔离、内容限制和隐私屏障 |
| 022-K | 权限、版本与幂等由服务端复核 | 本次实施将直接处置限定super_admin；原审核运营/危机岗仍保留查询与原案件权限；普通角色直接请求403；旧版本409重新确认；重放同键不重复处罚 |
| 022-L | 审计与注销 | 创建理由和直接解除理由均加密保存；记录操作者；不复制身份或匿名作品关联；注销后新请求和旧命令重放不得恢复账号资料 |

本次不增加自定义禁言时长、批量操作、代注销、资料修改或新角色。直接操作不撤销原处罚记录，只更新相应撤销状态；历史保留可解释性。普通案件与申诉入口仍可使用，直接处罚的申诉由超级管理员读取与处置。
