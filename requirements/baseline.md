# 鲤源池需求基线

版本：v0.2，2026-10-16。状态：已按独立评审修订，待复审、待用户人工批准G1；本文不是批准记录。

## 1. 来源与标记

- O：`requirements/original.md`，原始事实，只读；下文O:L表示行号。
- Q：`requirements/questions.md`，Q1–Q21及其用户书面答复，以及文末补存的B01原始答复、本次评审修订授权及采纳规则；“采用”仅确认对应问题所述规则。
- A：`requirements/audit.md`，提取与历轮记录；最终结论用于定位，不以AI建议替代原文或用户答复。
- R：`reviews/requirements-review.md` RR-001–RR-005及 `reviews/requirements-remediation.md` 的处理映射；具体细化依据Q文件文末用户授权直接采纳，不回写成此前答复。
- `approvals/`当前没有G1批准记录。原文与答复差异在第9节逐项说明，原文保持不变。

【已确认】仅指用户明确答复的业务规则。【原文事实】指原始输入的要求，尚不声称被逐项再次批准。【建议】用于优先级和验收组织方式，不新增已确认规则。【待确认】不作为默认业务行为。【授权采纳】指用户本次明确授权AI拟定并采纳评审处理办法，区别于既有原始答复。【假设】本基线不依靠未确认业务假设成立。

| 范围 | 内容 | 依据 |

| 首发隐私 | 黑名单、隐藏身份标签、注销；身份加密、角色授权、证据与备份保留 | Q5、Q15、Q19 |

【已确认，Q4、Q5、Q8、Q14、Q16、Q18】权限如下；许愿人/应愿人是业务关系，禁言/封禁是账号限制，均不是后台角色。未列出的跨角色授权不得由实现自行扩大。

| 主体 | 权限及限制 |
| --- | --- |
| 游客、未认证用户 | 可浏览公开内容；不可发布心愿、申请应愿或进入临时聊天。原文暖评权限随模块延期。 |
| 已认证学生 | 可发布、申请及参与本人匹配；正常回退由许愿人执行，完成由许愿人确认；仍受额度、状态、审核、黑名单及处罚限制。 |
| 审核运营 | 学生身份审核、普通内容审核、违规下线、词库维护、举报、禁言封禁及申诉处理；身份审核场景可看完整学生卡/姓名/学号并记录查看动作，其他页面脱敏；普通私聊仅能读审核案件中的命中消息。 |
| 危机处置人员 | 危机复核与误报解除，可看完整学号/危机内容；可处理举报、处罚、申诉；未授予学生身份审核权限。 |
| 超级管理员 | 全部权限，含后台账号/角色管理、保留证据删除。 |
| 受禁言账号 | 仅浏览，相关应愿暂停；7天禁言期满恢复权限，申诉成功可提前解罚。 |
| 受封禁账号 | 登录弹封禁提示，其他权限按游客；保留个人中心申诉专用入口，永久封禁不自动恢复。 |

首次认证仅华南理工在读学生；已通过者毕业维持资格。注销后可重新认证，但不把此规则解释为毕业生可首次认证或免除重认证资格检查。

## 4. 需求目录、优先级与验收标准

沿用审计编号，不因延期重排。优先级全部为【建议，待用户批准】：P0为首发核心及安全/权限/数据要求，P1为首发体验功能，P2为延期愿景。P1仍在首发，不表示可自行删减；P2仅确认延期，未确认未来上线日期或全部详细规则。验收用例编号使用对应REQ的后缀，便于后续设计和任务追踪。

### REQ-001 首发闭环与端边界

状态：【已确认Q1】；优先级：P0【建议】。来源：O:L3–38；Q1、Q15、Q18。

要求：交付第2节首发范围；延期模块不计入首发验收，不能把产品愿景直接变为首发承诺。

验收：001-A，已认证学生从发布、审核上架、被申请、确定应愿人、聊天、确认实现到提交还愿故事可完成完整流程，运营可处理相应审核与举报。001-B，检查首发功能清单与第2节一致，学生卡可上传而心愿/故事/聊天不提供业务图片能力。

### REQ-002 注册与学生认证

状态：【已确认Q4、Q8、Q14；注册绑定学号为原文事实】；优先级：P0【建议】。来源：O:L117–120；Q4、Q8、Q14。

要求：注册绑定学号，上传学生卡人工审核；每学号最多一个有效账号；驳回附原因、可重交；审核中前端显示审核中，不设审核时限；OCR延期。学生卡加密保存至注销，涉案图片适用REQ-018。

验收：002-A，未认证不能发布/申请/进入聊天，通过后可按状态授权操作。002-B，同学号第二有效账号被拒，注销后允许重新申请；首次非在读资格不通过，已认证者毕业不自动失效。002-C，待审可见审核中，驳回可见原因并能重交；审核查看完整资料有记录，其他运营页面脱敏。

### REQ-003 心愿字段与校验

状态：【原文事实；有效期与字数已确认Q17】；优先级：P0【建议】。来源：O:L49–58；Q6、Q17。

| 字段 | 规则 |
| --- | --- |
| 分类 | 必填；求助/组队/物品/脱单/技能交换/其他 |
| 内容 | 必填，最多500个Unicode码点；引导描述什么事、需要什么、时间地点 |
| 校区 | 必填；五山/大学城/国际校区/不限 |

### REQ-004 心愿生命周期与回退

状态：【已确认Q2、Q3、Q6、Q7、Q16、Q17】；优先级：P0【建议】。来源：O:L42–60；上述Q及Q文件补存B01。

要求：遵守第5节状态动作表；上架到期自动过期，应愿中不限时。修改或回退可选刷新；刷新从重新上架重算，不刷新保留原截止时间，已超时则过期；仅刷新也按修改规则重审。确认实现由许愿人操作，已还愿不得主动回退；注销清理不属于用户主动回退。处罚/拉黑例外解绑及注销目标按第10节执行。

补充【已确认，Q文件补存B01】：已实现回退应愿中前须检查活跃额度，已有3条时拒绝，先释放一条再回退。

验收：004-A，截止前可处理申请，到期后不能新申请或同意旧申请，应愿中跨原截止时间不自动终止。004-B，已实现回退保留应愿人并恢复原会话；回上架解绑、旧申请失效、旧会话只读；不刷新已过期的截止时间不能重新公开。004-C，审核中修改使旧审核失效，已上架修改先撤下重审；违规下线未解除限制不能重上架。004-D，已还愿回退拒绝，非授权者确认完成拒绝；正常与例外回退按第5节执行。

### REQ-005 活跃额度与唯一应愿人

状态：【原文事实及已确认Q11】；优先级：P0【建议】。来源：O:L42–47；Q11及Q文件补存B01。

要求：每心愿只确定一个应愿人，应愿中不接受新申请；单人已上架+应愿中心愿合计≤3。待审核不占额度，上架时检查；满额则审核通过后保留待上架，释放额度后本人申请上架并再次检查。

验收：005-A，并发同意不同申请至多一人成功；应愿中新增申请拒绝。005-B，已有3条活跃记录时并发审核上架不能产生第4条；满额记录可见待上架，额度释放后不会未经本人操作自动上架。005-C，已有3条活跃心愿时，已实现回退被拒，保留已实现及原会话只读；释放一条额度后本人再次回退可成功，活跃总数不超过3。Q文件补存B01记录了原始确认。

### REQ-006 应愿申请与通知

状态：【已确认Q4、Q11、Q12；留言长度为原文事实】；优先级：P0【建议】。来源：O:L64–65；Q4、Q11、Q12、Q17。

要求：认证后可对他人上架有效心愿申请，留言≤100码点；禁止自应愿，同人同心愿最多一条有效申请，可撤销后重申；回退旧申请失效，原应愿人可重申。许愿人可查看申请者公开主页与留言，一键同意。微信通知失败/未授权以站内未读兜底，不撤销业务结果。拉黑使存量待审/有效未匹配申请失效，解除拉黑不恢复；同意前再次复核当前条件，详见第10节。

验收：006-A，100码点通过长度检查、101拒绝；自应愿、未认证、重复有效申请、过期或应愿中心愿的申请均拒绝。006-B，撤销后可重申，旧失效申请不可同意；待审申请留言不向许愿人展示、申请不可同意，审核通过仍须复核当前业务资格；微信通知失败仍保留成功结果及站内未读通知，主页遵守REQ-008/018。

### REQ-007 临时匿名会话

状态：【已确认Q9、Q12、Q13、Q16、Q18】；优先级：P0【建议】。来源：O:L66、179；上述Q。

要求：确定应愿人后双方默认匿名聊天，可主动交换微信，不做私聊联系方式脱敏；仍扫描危险及其他违规内容。应愿中可写；已实现关闭写入、回退恢复；已还愿只读；解绑旧会话原双方只读，重匹配新建会话。普通消息至任一方注销删除；证据按REQ-018。处罚暂停、拉黑限制优先于普通会话状态；待审消息通过后须按第10节复核，失去送达资格则取消且不自动重放。

验收：007-A，无关用户不能读取会话，重匹配的新应愿人看不到旧会话；按状态与处罚/黑名单分别测试读写。007-B，正常联系方式按主动发送送达；普通违规命中仅人工通过且当前仍满足送达条件后送达，驳回告知原因；危险命中执行REQ-017。007-C，任一方注销后双方均不能读取普通旧消息，保留证据仅按授权访问。

### REQ-008 广场、本人记录、分享与还愿

状态：【已确认Q1、Q15、Q17；分类筛选/本人列表为原文事实】；优先级：P1【建议，首发】。来源：O:L7、34、67、123–124；Q1、Q15、Q17。

要求：分类筛选广场；我的心愿含草稿/详情/还愿/会话入口，我的应愿含列表/详情/会话入口。公众仅见已上架心愿及审核通过的还愿故事；许愿人和当前应愿人可看匹配详情。分享愿望或故事，每次访问重新授权，下线/过期/注销不可访问，不展示快照。提交故事即已还愿，故事单独审核；驳回可改稿重提，作者可撤回故事但不回退已还愿；无不写故事直接还愿路径。

验收：008-A，分类筛选不混入其他分类，普通用户不能读取他人草稿或非公开心愿；匹配双方可读所需详情。008-B，分享链接在状态变化后立即按当前权限返回，非公开正文不泄露。008-C，提交故事后心愿已还愿而待审故事不公开，审核通过后公开，驳回重提与撤回均不回退心愿状态。

- 解除当前匹配、所有旧未匹配申请失效；旧会话仍仅原双方只读（注销后删除普通消息）。不自动公开、不自动刷新期限、不自动重审。
- 许愿人后续可选择期限是否刷新并提交重新审核。上架前复核审核版本、处罚/违规/危机限制、额度及期限：选择刷新从新上架时间重算；未刷新且已过期转已过期，不可公开；满额按待上架流程；解除限制/拉黑不自动恢复旧匹配。
- 已还愿拒绝主动例外解绑，保持既有规则；账号注销的删除义务按10.4执行，不通过伪造主动回退实现。

验收：004-E/005-D/014-D/016-D，对起点应愿中/已实现、处罚/拉黑、双方合法退出、许愿人受处罚与否、额度满/未满、期限过/未过组合校验，目标均已撤下且不公开、不占额度、期限不变、匹配解除、旧申请失效、旧会话只读；无权退出或已还愿则拒绝。重新上架分别测试刷新、不刷新过期、满额及限制未解除。

### 10.2 延迟审核与业务复核（RR-002；REQ-006、007、015、016、018）

**内容判定通过不代表业务执行成功。** 实际公开、申请生效、消息送达及同意申请前，以执行时事实复核；复核与执行之间发生状态变化也不能绕过规则。无需指定数据库或队列实现。

| 对象/动作 | 当前必须满足的条件 | 不满足时结果 |
| --- | --- | --- |
| 应愿申请留言审核通过后生效 | 双方账号存在且满足认证与交互资格，无处罚/拉黑；申请未撤销/失效；心愿为当前允许的已上架版本且未过期、无确定应愿人；无其他同人有效申请 | 取消本次申请，不能展示成可同意或新建匹配 |
| 许愿人同意申请 | 上述条件继续成立，申请已审核通过；操作者为当前许愿人，唯一应愿人约束仍满足 | 拒绝，不创建关系和会话 |
| 普通私聊审核通过后送达 | 双方账号存在且认证有效，无交互处罚/拉黑；仍是原匹配原会话、应愿中、可写；消息未取消且为待审原版本 | 消息标记已取消，不送达，不因以后解罚/解除拉黑/回退恢复自动重放 |
| 心愿/故事待审通过后公开 | 作者未注销，内容未删除/撤回/改版，无当前处罚/违规/危机公开限制；当前状态与可公开条件满足；上架另查额度和期限 | 旧任务不公开；内容审核结果不解除业务限制，需本人后续按现有流程重提/申请 |

待审申请只是审核中的请求，计入同人一条未终结申请的去重范围，但不是许愿人可处理的有效申请。许愿人不见待审留言、不能同意；申请人可见审核中并撤销。审核驳回显示原因；普通消息被业务取消显示简明“当前状态已不支持送达”，不暴露对方隐私处罚细节。当前无已确认违规/危机证据资格的取消任务不得被提升为永久证据。

申请等待期间若撤销、对应心愿到期/改版/撤下/已匹配他人，或任一方拉黑、受到交互处罚、注销，待审申请立即失效，即使后续条件恢复也不自动生效，需重新申请。

状态在等待期间确认实现、还愿、解绑、拉黑、处罚或注销时，待审消息取消；注销删除普通正文和账号关联，后续任务只可终止，不得重新生成正文/通知/匹配。即使审核前状态已恢复，也不重放曾被取消的旧交互。公开内容的旧版审核失效，不妨碍当前符合条件的新版本重新正常提交。普通通知重试同样尊重注销删除；微信失败兜底不改变业务授权。

验收：006-C/007-D/015-D/018-E，分别先产生待审申请/消息/故事，再改变相关状态或撤回、到期、拉黑、处罚、注销，最后审核通过；断言不展示/不送达/不同意/不复活删除数据。恢复原状态后再次处理旧任务仍无效；新合规申请或消息另行审核。审核与取消并发时，最终不能产生违反当前权限的交互。

### 10.3 拉黑与旧申请（RR-003；REQ-004、006、014）

任一方拉黑生效时，双方在所有相关心愿下尚未形成匹配的待审/有效申请立即失效。双方不能新增申请或同意旧申请；已建立匹配不自动解除，由拉黑方按10.1选择退出，且拉黑期间私聊和待审送达均受限。解除拉黑不复活申请、消息或已解除匹配；未匹配且当前条件满足时可重新申请。撤销/失效请求不得因后续审核改回有效。

验收：006-D/014-E，对双方分别拉黑、有效申请/待审申请、拉黑与同意并发、撤销、解除、重申逐项检查：拉黑存在时不能新建匹配；旧申请解除后仍失效，新申请重新走审核，既有匹配仅在主动例外退出后解除。

### 10.4 注销后匹配与存活方记录（RR-005；REQ-004、005、007、008、018）

下表处理普通业务资料；合法证据只在案件权限内按REQ-018保留，不回流至普通列表、会话或分享。注销清理优先于待审任务、普通状态恢复及已还愿主动解绑限制。

| 注销方 | 注销前状态 | 存活方普通业务结果 | 状态/额度及可执行动作 |
| --- | --- | --- | --- |
| 许愿人 | 应愿中 | 删除其普通心愿、故事、申请与匹配关联，双方普通消息删除；应愿人仅获得通用“对方账号已注销，相关内容不可访问”结果，不保留真实身份/原文快照 | 该心愿不再存在于普通心愿体系，不占额度；应愿人不能回退/完成/还愿/继续聊天 |
| 许愿人 | 已实现 | 同上 | 不留孤立已实现记录给应愿人操作，不产生新活跃额度 |
| 许愿人 | 已还愿 | 同上，已公开故事与分享均不可访问 | 不为保存故事而保留已注销者普通内容；无可回退业务对象 |

| 应愿人 | 已还愿 | 许愿人自己的心愿及故事保留，去除已注销应愿人的身份、申请与匹配关联；普通会话删除，通用已注销提示不含可追溯普通账号标识 | 保持已还愿、不占额度、不可回退或再招募；作者可继续按原故事规则改稿重提/撤回，公开仍须满足审核与限制 |

应愿人注销后的已撤下心愿不刷新期限、不自动重审/公开；若同时受处罚、违规或危机限制仍须解除相应限制。许愿人自己普通内容如含已注销对方的可识别资料，删除相应身份引用，不用“自有内容”例外继续暴露对方；公开故事需重新审核后才恢复公开。此处仅保留存活者自有内容，不保留被注销者普通发言。已撤下仅许愿人可管理，原应愿人注销后无普通详情授权；保留证据仅案件角色可见。
