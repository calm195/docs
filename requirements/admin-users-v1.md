## 1. 来源与状态

【用户明确要求】本次会话原文：

> 增加首期需求：管理端可查询当前用户列表，并操作用户。设计方案

【用户明确确认】对范围问题“查询详情、查看处罚记录、按现有规则警告/禁言/封禁、通过申诉解罚；当前用户列表按平台现存小程序用户理解”，用户回复“采用上述范围”。据此将这些能力纳入首期需求；不将下文技术细化冒充已逐项批准的正式契约或 G3 设计。

【既有事实】[基线 v0.2](baseline.md)及其[G1](../approvals/G1.md)已覆盖 REQ-016 处罚申诉、REQ-018 隐私注销、REQ-019 管理权限；[悄悄鲤增量](whispers-v1.md)继续有效。本增量新增统一用户查询入口，处置沿用既有业务规则。旧文件保持原字节，本文件不改变其历史审批对象；原基线 SHA-256：`fed56e2811cd21c5c5d461a35d9ace525b6f9bc142a01a6a1f2048303da54810`。

【设计建议】分页、字段、接口及界面细化见[设计方案 v1.0](../design/admin-users-v1.md)，待按影响评审及人工确认。没有编写业务代码、部署、上线、Git 提交、推送或合并授权。

## 2. REQ-022 平台用户查询与处置入口

状态：首期范围已由用户确认；优先级建议 P0（首期支撑能力）。本条为 REQ-019 的新增能力，引用 REQ-016/018 约束，不重编号旧 REQ。

| 能力 | 要求与边界 | 可测试验收标准 |
| --- | --- | --- |
| 用户列表 | 管理端查询平台现存小程序用户，包括未认证、待审、通过、驳回以及正常、禁言、封禁用户；不等同于实时在线列表或后台管理员列表 | 022-A：上述类别均有可查询样本；游客、小程序会话和无后台角色账号不能访问；后台账号维护仍走原入口 |
| 查找与筛选 | 支持用户 ID 精确查找、认证状态与当前限制状态筛选、分页；同筛选下持续翻页不重复返回同一用户 | 022-B：不同筛选组合只返回匹配用户；空列表、最后一页、非法筛选及翻页重置可测；禁言到期按服务端当前时间计算 |
| 用户详情 | 查看脱敏基础资料、认证状态、当前有效处罚及权限范围内处罚历史；列表/详情不提供完整姓名、学号、学生卡、微信标识、聊天或胶囊正文及匿名作者关联 | 022-C：直接请求及响应原文均不含越权字段；有认证/危机权限也须进入相应授权工作台读取敏感资料并留迹 |
| 处罚入口 | 从用户进入有权处置的案件，按既有轻微警告、一般禁言7天、严重永久封禁规则操作；必须具备违规依据、精确内容版本与理由 | 022-D：缺依据、目标与案件不匹配、版本冲突、越权均拒绝；同一违规重试不重复处罚；处罚后刷新得到权威状态 |
| 处罚记录与申诉 | 查看授权范围内的处罚记录，跳转关联申诉；申诉成功按原规则提前解罚，保留处理理由 | 022-E：无申诉不提供任意解罚；处理申诉后只撤销对应处罚，其他有效处罚继续生效；不恢复已失效互动或自动公开内容 |
| 隐私与注销 | `deleting` 及已清理账号退出普通用户列表/详情；既有案件证据仍仅在案件权限内读取 | 022-F：翻页、旧详情、旧游标、处罚/查询并发遇到注销均不能回显普通资料或复活账号；普通查询不访问备份/证据库 |
| 授权与留迹 | 审核运营、危机处置人员、超级管理员可访问脱敏用户入口；具体案件正文和处置逐次按案件权限检查，角色被撤后立即拒绝 | 022-G：普通运营不能借用户入口读取危机案，危机人员不能借此读取学生卡；查询/操作审计可追踪且满足 REQ-018 清理要求 |

## 3. 首期排除项与不变规则

本次不新增管理员代改用户资料、重置学生身份、创建学生账号、代注销/删除用户、直接解罚、批量处罚、批量导出、在线监控、完整学号/姓名搜索、按树洞昵称反查作者或全量内容浏览。后续如需增加，另行明确需求及权限影响。

REQ-016 的警告30秒确认、禁言7天、永久封禁、关系暂停/例外退出及申诉解罚规则保持不变。新入口不赋予无案件依据处罚权限；危机隔离沿用 REQ-017，不当作普通封禁按钮。REQ-018 的注销屏障、证据隔离和备份重删继续适用。
