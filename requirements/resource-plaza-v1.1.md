## 2. 字段与复制规则（REQ-023）

以下类型及上限作为本版可执行设计值，后续正式契约应使用相同用例验证，不由各端自行取值。

| 字段 | 规则 | 验收 |
| --- | --- | --- |
| 标题 `title` | 必填、单行纯文本，去首尾空白后1–100个 Unicode 码点 | 023-I：100通过、101/全空白拒绝；HTML按文本显示，不执行 |
| 分类 `category_id` | 必选一个当前启用的单级分类，以稳定 ID 引用 | 023-J：不存在、停用分类不能录入或上架；前台显示分类名称，不接受自定义分类文本代替 ID |
| 简介 `description` | 可选纯文本，最多2000码点，允许换行；空值统一为空字符串 | 023-K：缺省/空白可保存；2000通过、2001拒绝；详情显示完整简介，列表只显示摘要 |
| 下载链接 `download_url` | 必填，一个绝对 HTTP/HTTPS URL，去首尾空白后最多2048个 UTF-8 字节；不得有嵌入式用户名密码、内部空白或控制字符 | 023-L：合法链接保存后保留路径、查询参数及片段；非HTTP协议、空主机、超长值拒绝；语法通过不等于网盘可用 |
| 提取码 `extraction_code` | 可选单行文本，去首尾空白后1–64码点，大小写保留；空白/缺省归一为 null | 023-M：有/无提取码均可上架；不得把无提取码显示为字符串“null”；不限定为某网盘的四位码 |
| 系统字段 | ID、状态、资源版本、内容版本、创建/更新时间及最近上架时间由服务端维护 | 023-N：客户端不能覆盖系统字段；每次有效修改递增资源版本，旧版本不能覆盖新内容 |

【已采纳并细化】详情提供“复制下载信息”和“仅复制链接”。有提取码时下载信息为两行：第一行原链接，第二行 `提取码：<原提取码>`；没有提取码时只复制原链接。“仅复制链接”始终不附加提取码。列表不下发链接或提取码，详情仅向有权用户展示。

023-O：每次复制前重新读取该资料的当前可用下载信息，核对当前账号和资源版本；下架/失权时不能从旧详情缓存继续复制。资料换版时先刷新详情，由用户再次点击复制；剪贴板成功回调后才提示成功。已到达客户端或已复制到平台外的数据不能追溯撤回。

## 3. 分类、搜索与页面范围（REQ-023）

【已采纳】分类与关键词取交集；关键词匹配标题或简介包含关系，去首尾空白后为空表示不筛选。中文字面匹配，ASCII字母忽略大小写；`%`、`_`、反斜杠、引号均作普通字符。不增加拼音、纠错、语义或外部文件正文搜索。

【设计细化】关键词最多100码点；筛选在服务端、分页截断前完成。资料按创建时间及ID倒序，编辑/重新上架不置顶；默认20条、最大50条，分页不承诺冻结快照。分类或关键词变化后重置分页，晚到响应不能污染新查询。

023-P：覆盖标题命中、仅简介命中、分类交集、空白词、100/101码点、中文、ASCII大小写及特殊字符；未上架资料不得进入结果或计数。小程序有列表、详情、认证引导和加载/空/失败状态；首页仅显示通用入口，不向未认证用户展示任何资料摘要。

【采纳分类维护并细化】后台支持分类创建、改名、排序和启用/停用，不支持多级分类或硬删除。名称去首尾空白后1–30码点，单行纯文本且按ASCII忽略大小写唯一；排序值为0–9999整数，较小者在前，同值按ID排序。新建分类默认启用。只要仍有关联资料（含草稿/下架），即拒绝停用；先将这些资料迁至其他启用分类，再停用。

023-Q：重名、超长或旧版本修改拒绝；分类停用与资料创建/换分类/上架并发时，不产生资料指向停用分类的状态。改名保持ID和资料归属不变；全部列表与详情使用当前分类名称。小程序仅返回启用分类且不附资料数量。

## 4. 管理权限与编辑上下架（REQ-019/023）

| 主体 | 分类/资料后台查询、录入、编辑、上下架、分类维护 | 小程序资料读取/复制 |
| --- | --- | --- |
| 审核运营 `review_operator` | 允许 | 后台会话不代替学生会话 |
| 超级管理员 `super_admin` | 允许 | 同上 |
| 仅危机处置 `crisis_operator`、无角色后台账号 | 拒绝本模块资料管理；保留原有案件权限 | 同上 |
| 已认证、存续、未封禁学生 | 拒绝后台能力 | 允许；禁言不影响读取和复制 |
| 游客、未认证/待审/驳回、封禁、注销中/已注销或无效会话 | 拒绝 | 拒绝 |

多角色账号只要持有审核运营或超管角色即可管理；当前角色及会话逐次检查，不能靠历史角色快照授权。023-R：逐行验证读取及写入正反例；认证通过不授后台权，角色撤销后在途旧页面不得发起有效修改；错误响应不得带出资料信息。

| 当前状态 | 允许动作 | 成功后的状态与约束 |
| --- | --- | --- |
| 无记录 | 创建 | `draft`；保存即校验全部必填资料，保存本身不上架 |
| `draft` 未上架 | 编辑、上架 | 编辑后仍为 draft；上架前核对字段、分类、当前权限与版本，成功为 published |
| `published` 已上架 | 查看、下架 | 不能直接保存内容修改；下架成功为 offline |
| `offline` 已下架 | 编辑、重新上架 | 编辑后仍为 offline；重新上架须显式操作，不因保存或解除账号限制自动发布 |

023-S：已上架资料点击“编辑”先说明影响并确认下架；下架失败不进入可写编辑状态。下架成功后，即使取消编辑或保存失败，也保持下架；重新上架始终是单独操作。主动下架要求1–500码点非空理由；“为编辑下架”可默认填入“修改资料信息”，允许修改。

023-T：全部后台写操作带幂等键；修改/上架/下架/分类更新带对应资源版本。重复同一命令不重复创建、上架或留迹；其他人员已修改时返回版本冲突，重新读取并由操作者确认，不自动覆盖。错误结果或网络超时不显示成功；实际已生效的下架不可因客户端重试而恢复。

【维护边界】不提供资料或分类硬删除、定时发布、批量导入、双人审核或系统内投稿表单；资料管理操作记录后台操作者、动作、目标、版本、时间及必要理由，技术日志不记录链接、提取码或全文。

## 5. 资料反馈与微信投稿（REQ-023）

【用户明确要求】资料详情提供“资料反馈”，选项固定为“有效、链接失效、年代久远、不全”，不提供资料举报按钮，也不把反馈发送到举报、处罚或危机案件接口。

【设计细化】每个当前有权读取且无禁言/封禁的学生，对每份资料的当前内容版本保留一个有效选项，可重新选择以更新；同账号重复提交不重复计数。反馈不收集自由文本、附件或联系方式。认证有效但禁言者可读、复制和查看投稿二维码，不可新提交/修改反馈。

023-U：四个选项的文案及后台归类一致；重复点击不重复计数，改选后旧类减一、新类加一；下架、换内容版本或失去资格后，旧页面提交被拒绝并刷新。保存了新的内容版本后，旧版反馈退出当前统计；后台仅看到四类汇总，不看到学生身份。反馈不自动下架资料或处罚任何人，负责人核对后使用既有编辑/下架流程。

【用户明确要求并设计细化】资料列表提供“资料投稿”入口，点击弹出运营提供的固定二维码图片，提示“添加资料负责人微信，备注‘资料投稿’”。沿用本模块认证入口，未认证者先进入认证引导；这项门禁约束页面交互，不将静态联系图片当作身份保密资料。负责人在微信接收资料后，由有权后台人员按正常录入/上架流程整理。

023-V：入口在正常列表与空结果时均可用；弹窗显示指定完整二维码，保持比例、可查看大图并关闭；不开投稿表单、不上传资料、不自动发送微信消息。图片缺失/加载失败显示明确提示，不能展示虚构二维码、微信号或宣称投稿已完成。

023-W：二维码作为固定静态图片随小程序资源发布，当前不新增后台图片上传/替换接口；替换时形成新资源版本并重新构建验证。仅使用资料方提供的负责人联络图片；初始图片、内容有效性和真机可识别结果待提供及核验，本次不生成替代二维码。

## 6. 既有规则与外部边界

资料上架由有权运营人工核对内容和链接，首期没有独立双人审批。REQ-015 中已明确的心愿/留言/故事自动审核继续有效，本次不宣称这些已有扫描已覆盖资料或外部文件。运营不能借此公开学生身份、联系方式或其他受限信息；本设计不自动访问外部链接，不扫描、托管或代理下载网盘文件。

固定投稿二维码是用户本次明确增加的图片展示范围，不据此开放业务资料图片、用户图片上传或文件托管；既有其他媒体范围保持原样。

认证约束只控制平台内获取。已复制链接、外部网盘权限、链接失效及真实下载结果仍需资料提供方维护。注销清除学生反馈的普通关联并退出统计，不删除由后台维护的共享资料；不保留长期学生浏览轨迹。四类反馈是资料质量信号，不等于内容审核或安全案件结论；既有适用的内容/隐私屏障不能被普通重新上架绕过。

## 7. 交付与剩余依赖

字段、提取码、管理角色、编辑下架、分类维护和搜索方案已采纳并在本版细化；反馈选项和固定二维码投稿入口来自用户本轮明确调整。当前待提供的是实际分类/资料、有效外链样本、负责人固定二维码图片、目标环境和测试账号；责任人、交付日期尚未指定，不编造资料事实。
